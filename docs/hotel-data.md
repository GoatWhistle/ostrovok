# Как получить сведения об отеле бесплатно

> По умолчанию `HOTEL_DATA_MODE=free`: коммерческие каталоги отелей отключены даже при наличии
> ключей. Источники — уже загруженный OpenStreetMap и публичные страницы; структурированные
> сведения сайта читаются без платного API. Полнота данных по всем отелям России не подтверждена.

**Читайте, если** нужны услуги, контакты и сведения об отеле без расходов на API · **Связано:**
[запуск](running.md) · [архитектура](architecture.md) · [ограничения](limitations.md)

## Что работает в бесплатном режиме?

| Источник | Что получаем | Предел |
|---|---|---|
| Локальный OpenStreetMap | Название, адрес, координаты, звёзды, сайты, контакты и опубликованные теги | Поля есть не у каждого отеля; теги не подтверждают наличие номера на даты |
| Публичные страницы отелей | Видимый текст, ссылки, JSON-LD `Hotel` и `LodgingBusiness` | Страница может быть недоступна; её принадлежность отелю и каждое условие проверяются по источнику |
| JSON выдачи Островка | Название номера, цена проживания, питание, опубликованный остаток и оснащение | Только предложения на выбранные даты и гостей; внутренний интерфейс сайта может измениться |
| Существующий Wikidata lookup | Координаты географических объектов | Это не каталог номеров или услуг всех отелей |

[Выгрузки Geofabrik](https://download.geofabrik.de/) бесплатны и не требуют API-ключа.
Использование OSM требует [атрибуции и соблюдения ODbL](https://www.openstreetmap.org/copyright).
Большие выгрузки обрабатываются локально; публичный API OSM не используется как национальная
база для каждого пользовательского запроса.

[Wikidata](https://www.wikidata.org/wiki/Wikidata:Licensing) предоставляет структурированные
данные под CC0. Публичные интерфейсы ограничены по нагрузке; это не гарантия присутствия
каждого российского отеля. Отдельный импорт каталога отелей Wikidata пока не реализован.

Режим касается источников сведений об отелях. LLM и эмбеддинги настроены отдельно: этот режим
не делает облачные модели бесплатными и не меняет их выбор.

## Как сайт отдаёт сведения без API-ключа?

Агент читает публичную страницу через существующий `read_web_page`. Кроме видимого текста,
`HotelMetadata` извлекает JSON-LD из `application/ld+json`: название, адрес, координаты, контакты,
удобства и другие явно опубликованные поля. Обрабатываются обычные записи, массивы и `@graph`.
JavaScript не выполняется; удалённые JSON-LD-контексты не загружаются. Платного запасного
источника нет.

До десяти записей с одной страницы добавляются к тексту как **непроверенные сведения**.
Один блок ограничен 64 000 символами, итоговые метаданные — 16 000. Веб-страница ограничена
1 МБ; закрытые сетевые адреса и перенаправления проверяются существующим читателем.

Принадлежность страницы конкретному отелю и смысл цитаты проверяет существующий механизм
веб-доказательств. Названия недостаточно: одноимённый объект в другом городе не подходит.
Поисковый результат может вести к посреднику; сам по себе сниппет не считается подтверждением.

[Schema.org Hotel](https://schema.org/Hotel) задаёт смысл полей:
`numberOfRooms` — общее число комнат, а не свободные номера; `amenityFeature` не гарантирует,
что услуга бесплатна или включена в тариф. Ложное значение удобства сохраняется ложным,
а не превращается в подтверждённое наличие. JSON-LD не заменяет актуальное бронирование.

Чтение публичной страницы не даёт права копировать все тексты и фотографии в свой каталог.
Доступность страницы, правила сайта и условия использования проверяются для конкретного
источника. Механизм использует сведения и цитаты как доказательства; отсутствие поля означает
неизвестность.

## Почему Nuitee, Яндекс и Bronevik отключены?

У Nuitee [контент и базовый поток объявлены бесплатными](https://docs.liteapi.travel/reference/api-pricing-usage-costs),
но бесплатность зависит от условий использования и соотношения поисков к бронированиям.
Поставщик оставляет возможность изменить условия для нестандартного использования.
Places и ценовые индексы оплачиваются отдельно; они не используются в бесплатном режиме.
[FAQ](https://docs.liteapi.travel/docs/faq) также требует карту для производственного ключа.
Поэтому массовое извлечение каталога нельзя обещать как безусловно бесплатное.

У [Яндекс Путешествий](https://yandex.ru/dev/travel-partners-api/doc/ru/getting-started) и
[Bronevik](https://bronevik.com/ru/api-solutions) нужны партнёрские доступы. Нулевая стоимость
нашего сценария не подтверждена; это не утверждение, что любой их API-вызов платный.
Они исключены из обязательного бесплатного пути.

`HOTEL_DATA_MODE=free` не создаёт клиентов коммерческих API и `MatchHotelCatalog`, а команды
`sync-nuitee` и `match-nuitee` завершаются до сети и базы. Ранее импортированные сведения
остаются доступными из PostgreSQL. Предложения на даты запрашиваются у публичного сайта
Островка. Отключить этот источник можно через `OSTROVOK_SITE=off`; тогда проверка номеров
возвращает `provider_unavailable`.

## Откуда берутся номера и цены Островка?

Сервер читает тот же JSON, который загружает [сайт Островка](https://ostrovok.ru/).
`GET /hotel/search/v2/site/serp` открывает поиск, `POST` на тот же путь возвращает страницы
предложений. API-ключ, учётная запись и оплата запроса не используются. Это внутренний,
недокументированный интерфейс сайта; его доступность и бесплатность в будущем не гарантированы.

Область поиска ограничена квадратом с полуразмером 350 м вокруг координат отеля. В запрос
передаются даты, число взрослых, рубли и название без общих слов «отель», «гостиница».
Источник поддерживает российское резидентство. Дети и их возраст пока отсутствуют в контракте
проверки предложений; их нельзя подменять взрослыми или придуманным возрастом.

Предложения возвращаются только при единственном совпадении по существующим правилам
[проверки отеля](#что-осталось-от-сопоставления-nuitee). Неполная выдача и незавершённый поиск
дают `provider_error`. Нет совпадения или есть несколько — `hotel_unmapped`. Эти состояния
не означают отсутствие свободных номеров. Постоянная связь с каталогом и категории в таблицу
`rooms` этим путём не записываются.

Цена берётся из `show_amount` и относится ко всему проживанию для указанного состава гостей.
Одинаковые названия с одинаковыми питанием и оснащением объединяются по меньшей цене;
условия питания сохраняются раздельно. Нулевой остаток не показывается как доступное предложение.
Этаж и сторона здания остаются неизвестными. Выдача поиска может содержать только один тариф
отеля и не является полным каталогом его номеров. Бронирование и проверка prebook не подключены.

Успешный ответ кэшируется на десять минут с исходным временем проверки, отсутствие совпадения —
на минуту. Даты и число взрослых входят в ключ кэша; одинаковые одновременные запросы
объединяются. Разрешены две поисковые операции одновременно, до трёх страниц и 40 секунд
на операцию. После ошибки сайта вымышленные тарифы не подставляются.

## Что осталось от сопоставления Nuitee?

Код сохранён для отдельно согласованного партнёрского режима `HOTEL_DATA_MODE=partner`.
Сейчас этот режим не выбран. При его включении координаты дают кандидатов, название и адрес
проверяются локально; единственный кандидат повторно сверяется по detail-карточке до записи.

Пороги: RU, не больше 300 м; подтверждённый адрес и совпадение имени или сходство от 0,9.
Без подтверждённого адреса требуется точное нормализованное имя в пределах 50 м.
Конфликт адреса запрещает связь; пять страниц по 200 кандидатов должны дать полную выдачу.
Неоднозначность, неполная выдача и несогласованная карточка запрещают автоматический импорт.
Пороговые правила не являются измеренной точностью; парсер адресов не заменяет ФИАС.

Код записи блокирует локальный отель, не заменяет существующий ID другим и не присваивает один
ID поставщика двум локальным объектам. Этот путь проверен локальными ответами и PostgreSQL,
но реальный охват Nuitee по России не измерен.

## Как подгружается подробное окружение по России?

Основные слои OSM хранятся в PostgreSQL: отели, здания, объекты интереса, дороги,
береговая линия и пляжи. Импорт зданий и пляжей собирает составные полигоны из OSM relations.
Части зданий сохраняются отдельно; отель связывается с основным контуром.
При импорте сохраняются все теги выбранного объекта, включая поля, которых нет в реестре
характеристик. Команда обновления тегов дополняет существующие отели по их OSM ID.

Для сцены выбранного отеля, линии обзора и пустого векторного тайла на масштабе 16 и выше
система проверяет сохранённое покрытие области. Готовая локальная сцена отеля возвращается сразу; внешний запрос нужен при отсутствии контура или окружения. Если покрытия нет, небольшой участок
запрашивается через Overpass. Успешный ответ записывается в те же таблицы вместе с источником,
временем получения и признаком полноты. Полный ответ, включая пустой, используется 30 дней;
неполный — пять минут. Полнота относится к полученному снимку OSM и не доказывает, что на
местности размечены все препятствия.

По умолчанию выбран [бесплатный сервер Private.coffee](https://overpass.private.coffee/),
который допускает использование в приложениях без регистрации. `GEOGRAPHY_API_URL` задаёт
другой совместимый сервер. Запрос ограничен областью 0,01 квадратного градуса, 12 МБ ответа
и 20 секундами ожидания с учётом очереди. После отказа действует пауза; отказ не записывается
как пустая область. Работающая локальная база остаётся доступной при недоступном API.

Рельеф Сочи читается из локального Copernicus GLO-30. Для других областей небольшие тайлы
загружаются из [Mapterhorn](https://mapterhorn.com/) и сохраняются на диске.
Увеличение тайла для карты не добавляет детализацию к исходной модели высот.

## Можно ли бесплатно получить всё для каждого отеля России?

Подтверждённого источника со всеми отелями, услугами, категориями и актуальными остатками нет.
Бесплатный путь дополняет локальную базу опубликованными данными; пропуски остаются явными.
API [реестра Росаккредитации](https://tourism.fsa.gov.ru/ru/resorts/showcase/hotels) и условия
машинной выгрузки в этой проверке не подтверждены. Реестр не обещает актуальные тарифы и остатки.
