# API

## Диалог и подборка

`POST /api/v1/chat/messages` принимает сообщение, необязательный `conversation_id`, регион,
выбранный отель и язык `ru`/`en`. Ответ содержит историю, текущий полный запрос и результаты
поиска. Сервер хранит историю в PostgreSQL. При уточнении DeepSeek V4.1 Flash собирает актуальный
запрос из предыдущего и нового сообщения; поиск проверяет факты из БД и вызывает расчёт объектов
рядом по текущему запросу. Модель не задаёт значения фактов.

`GET /api/v1/chat/conversations/{conversation_id}` восстанавливает историю и повторно рассчитывает
выдачу. Идентификатор хранится в браузере; регистрация и права доступа к диалогу в прототипе
отсутствуют. Неверный идентификатор даёт `404 not_found`; недоступный LLM — `503 model_failure`.
Ответ сообщает число показанных кандидатов, максимум 20, а не общее количество отелей.

`GET /api/v1/hotels/{hotel_id}` отдаёт карточку с активными фактами и массивом номеров. Номер
включает вместимость, диапазон этажей, фасады, цену и включённые услуги, если они известны.
В текущем срезе Сочи записей о номерах нет; интерфейс сообщает об отсутствии данных.

`GET /api/v1/hotels/{hotel_id}/offers?check_in=YYYY-MM-DD&check_out=YYYY-MM-DD&adults=2&residency=ru`
запрашивает актуальные тарифы для выбранного отеля. Даты ограничены ближайшими 730 днями и
30 ночами. Ответ всегда различает `provider_unavailable` (нет партнёрского подключения),
`hotel_unmapped` (нет проверенного соответствия каталогу), `provider_error`, `sold_out` и
`available`. Цена относится ко всему проживанию на указанные даты в валюте ответа поставщика;
`checked_at` показывает момент запроса. `floor_number` остаётся `null`, пока отель не подтвердил
конкретный этаж. Тарифы не доказывают возможность бронирования без проверки на шаге prebook.

Полная форма запросов и ответов: [OpenAPI](api/openapi.yaml).

> HTTP API бэкенда {{PRODUCT}}: {{N}} методов под префиксом `/api/v1`. Спецификация OpenAPI генерируется
> из кода и руками не пишется; из неё же генерируются типы фронтенда. Ошибка у всего API одна по
> форме: машинный `code` и `message` для логов.

## Как выглядит ошибка?

Тело ошибки одно на весь API:

```json
{
  "code": "{{snake_case_code}}",
  "message": "{{English message for logs and developers}}"
}
```

`code` — машинный код: фронтенд показывает текст из своих словарей по ключу `errors:api.<code>`.
`message` — по-английски, для логов и разработчиков; в интерфейс не попадает.

| Статус | Когда |
|---|---|
| 400 | {{Запрос корректен по схеме, но неверен по смыслу: истёкшая ссылка, неверный код}} |
| 401 | Нет входа |
| 403 | Чужая роль |
| 404 | Записи нет или она чужая |
| 409 | Действие недоступно в текущем состоянии: {{примеры}} |
| 422 | Запрос не прошёл проверку схемы или правил |
| 503 | {{Внешний сервис не отвечает, запасного пути нет}} |

| `code` | Статус | Когда |
|---|---|---|
| `{{code}}` | {{409}} | {{Условие}} |

## Как меняется контракт?

Несовместимое изменение выкатывается в три шага: фронтенд понимает обе формы → бэкенд переходит на
новую → старая форма удаляется. Типы фронтенда пересобираются из OpenAPI в том же изменении, где
меняется API.
