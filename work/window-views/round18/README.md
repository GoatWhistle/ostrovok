# Прогон 50 запросов на одной сборке, 28 октября 2026

Образ бэкенда `sha256:437e1298910e4d7c37dffeb5a298969e8304f34516cb50c8e03ae20494debff7`
(`hotel-agent-backend:run50-20261028`), не менялся за время прогона: скрипт сверяет образ до и
после каждого случая и прерывается при подмене. Набор запросов зафиксирован в `cases-50.json`
до прогона и не правился. Запросы шли по одному, через тот же путь, что и браузер.

## Результат

**32 случая из 50 прошли независимый аудит, 18 не прошли.** Сводка: `summary.json` (как записал
прогон) и `summary-reaudited.json` (после исправления ошибки в самом аудите, см. ниже).

Прошли, по городам: Санкт-Петербург (Исаакиевский собор — четыре случая, Эрмитаж,
Петропавловская крепость, «Аврора», Нева), Казань (кремль, Кул-Шариф — три случая), Москва
(Останкинская башня — два случая), Сочи (море — четыре случая), Новороссийск, Геленджик, Анапа,
Владивосток, Махачкала, Пятигорск (Бештау), Красноярск (Енисей), Волгоград (Мамаев курган), плюс
пять особых сценариев: без города, двусмысленный, невозможный этаж, выдуманный объект,
противоположная сторона.

## Исправление в самом аудите

Единственная найденная ошибка геометрии — `clear_ray_crosses_profile_obstruction` на запросе
«вид на купол Исаакиевского собора с седьмого этажа» — оказалась дефектом измерительного
скрипта, а не бэкенда. В профиле препятствий на луче длиной 141,6 м значился объект `r3229898`
на 139,5–140,7 м с высотой 87,8–91,8 м. Это `target_part_id` — **сам собор**. Аудит считал цель
препятствием на пути к себе. Цель и её родитель теперь из профиля исключаются; обе гостиницы
(`SO/` и «Астория») проходят чисто.

## Как выглядят 18 отказов

Семнадцать из восемнадцати — один и тот же отказ `no_geometric_target_evidence`, шестнадцать с
ним же `no_results_for_resolvable_target`. Один отдельный: `teletskoye` — `wrong_location`.

| Случай | Город | Цель |
|---|---|---|
| kremlin, basil, moscowcity | Москва | Кремль, Василий Блаженный, Москва-Сити |
| elbrus, elbrus_low, mashuk, klyuchevskaya, avacha | Кисловодск, Пятигорск, Камчатка | горы |
| volga_nizhny, volga_samara, volga_volgograd, onega | Поволжье, Петрозаводск | реки и озёра |
| goldenbridge, russianbridge | Владивосток | мосты |
| nevyan | Невьянск | башня |
| sea_floor1, sea_east | Сочи | море с первого этажа, на восток |

Форма отказа одинаковая: город распознан верно, уточняющий вопрос не задаётся, **ноль
рассчитанных лучей и ноль отелей в выдаче**. То есть расчёт видимости для этих целей вообще не
запускается.

Проверено, что дело не в отсутствии данных: по имени в локальном слое есть «Машук» (22 записи),
«Кремль» (203), «Волга» (218), «Онежское» (43), «Бештау» (30), «Енисей» (277). При этом Бештау и
Енисей проходят, а Машук и Волга — нет. Значит, объекты есть, но для части целей цепочка
«распознать ориентир → получить физическую геометрию → построить луч» не доходит до конца.

Отдельно подтверждено на Онежском озере: ориентир теперь **распознаётся правильно**
(`landmark_identity accepted=1 rejected=3`, «Долгое озеро» и «Угольная Ламба» отклонены по
существу) — это исправление той же сессии. Но дальше пожелание уходит в общий цикл агента и
заканчивается как незавершённое после 14 вызовов инструментов, без расчёта видимости.

Ещё одно наблюдение по Эльбрусу: в данных он называется «Эльбрус Восточный», а запрос ищет
«Эльбрус». Это несовпадение имени, а не отсутствие объекта.

## Что это значит

Цель задачи — «определять отели с конкретным видом из окна» — **выполняется для 32 случаев из
50 и не выполняется для 18**. Считать её закрытой нельзя. Следующий шаг не в геометрии луча:
она работает и проверяется независимо там, где запускается. Разбираться нужно в том, почему для
этих целей расчёт видимости не запускается — классификация пожелания как видового, выбор
физического объекта вместо точки POI и получение его геометрии.

## Что проверено и отпало

Четыре правдоподобные причины отказов проверены прямыми вызовами на стенде и **не подтвердились**.
Записано, чтобы их не проверяли заново.

| Гипотеза | Проверка | Итог |
|---|---|---|
| Запрос не распознаётся как видовой | `parse_query` на трёх запросах | отпала: все три дают `landmark_view` со 100 км радиусом |
| Объекта нет в локальных данных | поиск по имени в `pois` | отпала: «Машук» 22, «Кремль» 203, «Волга» 218, «Онежское» 43 |
| Ориентир не находится среди кандидатов | `named_places.candidates` с городским bbox | отпала: «Московский Кремль» первый из 16, «Машук» единственный точный |
| Текст пожелания не совпадает с текстом видового запроса | сравнение `spatial.source_text` и терминов плана | отпала: совпадают дословно во всех трёх |

Дополнительно: Бештау проходит, Машук нет, хотя оба — узел `natural: peak` без тега высоты, и
Машук к гостиницам ближе. То есть дело не в типе цели и не в расстоянии.

Остаётся проверить то, что дальше по цепочке: доходит ли видовой запрос до
`EvaluateWindowViews` при разборе конкретного пожелания и что возвращает подготовка лучей для
точечной цели без геометрии. Прямой след: в живом прогоне Машука пожелание отработало **18
вызовов инструментов общего цикла агента** и закончилось незавершённым — то есть расчёт
видимости либо не запускался, либо вернул пустое, и агент пошёл искать подтверждение сам.
