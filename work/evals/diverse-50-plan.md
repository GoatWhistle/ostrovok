# План проверки 50 сообщений на основном стенде

Набор `diverse-50-cases.json` зафиксирован до отправки запросов. 40 независимых запросов и
5 диалогов по 2 сообщения: всего 50 новых пользовательских сообщений. Прежние 10 кейсов
не повторяются дословно. Стенд — `http://127.0.0.1:8080`, API чата за тем же nginx, которым
пользуется сайт. Версия продукта во время серии неизменна; SHA и настройки модели
фиксируются в метаданных. Параллельно обрабатываются не более двух независимых диалогов.
Это проверка качества, а не нагрузочный тест. Проверка платной модели явно запрошена пользователем.

Для каждого сообщения сохраняются HTTP-статус, время, ID диалога, актуальный запрос,
ответ ассистента, исправления, извлечённые и нераспознанные пожелания, первые три отеля
с доказательствами и качества совпадений для всей возвращённой подборки. Геометрия зданий
в журнал не включается. Первое сообщение каждого диалога отправляется с пустым ID;
второе получает ID первого. Для запросов с результатами отдельно проверяется чтение
карточки первого отеля и доступность ссылок на карту (ограниченная выборка до 10 ID).

Критерии разбираются отдельно:

- HTTP и время: успешность обработки, ошибки, медиана и 95-й процентиль.
- Место: нужный город, честный отказ для неподдерживаемого места или уточнение без города.
- Смысл: сохранены все пожелания, точные ограничения, отрицания, единицы и названные ориентиры.
- Честность: невозможные услуги, виды, тарифы и доступность не названы подтверждёнными без источника.
- Рекомендации: подтверждены ли все пожелания первого кандидата; есть ли `none`, `unknown`
  или нулевая оценка; не скрывает ли ответ ассистента нехватку подтверждений.
- Контекст: в пяти продолжениях сохранены прежние действующие условия, отменённые удалены.
- Карта и карточка: ссылки реально читаются; точка у берега не считается доказательством вида
  из комнаты, а маршрут до моря — доказательством маршрута до нужного пляжа.

Пустой список при противоречии, отсутствие данных и несуществующий город сами по себе не
считаются сбоем. `full` проверяется на соответствие смыслу запроса, а не принимается за истину.
Итог содержит отрицательные случаи и ограничения. Во время основной серии исправления не
вносятся; повторы после исправлений, если потребуются, учитываются отдельно.
