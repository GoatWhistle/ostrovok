# Исследование данных: результаты на основном стенде

Задача: обработать желание «хочу отель высоко в горах около Владикавказа» по доступным
данным без заранее заданного поля горного отеля. Первоначальный диалог пользователя
`92949e4d-198e-411d-95ef-fd2cec3fef08` возвращал городские отели и оставлял горы непроверенными.
Прогоны нового механизма отправлялись в отдельные реальные чаты на `localhost:8080`.

## Что реально выполнено

Агент получил сведения о заполненности данных и выбрал инструменты исследования. Среди
выбранных действий были расширение области, чтение инвентаризации и измерение DEM. Значения
высот, число подходящих записей и совпадения критериев вычислил исполнитель. Придуманный
путь поля и подмена исходного пожелания другим отклоняются. Проверка неизвестного этажа
не использует высоту здания; питание за отдельную плату не доказывает включение завтрака.

## Предел результата

Модель выбирает оценочные пороги для расплывчатого желания. В повторе №12 она использовала
только высоту для финального условия, хотя инструмент возвращал и перепад. Это основание
для `partial`, а не доказательство горного типа местности для любого запроса. Нужен дальнейший
контроль качества выбора критериев. Девять точек DEM не дают полного анализа рельефа.
Отсутствующие номера/услуги и семантические ошибки из прогона 50 сообщений не считаются
решёнными. Прогон 50 относится к старой фиксированной версии и не повторялся после изменений.
