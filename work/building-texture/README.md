# Building texture experiment

Задача: получить текстуру здания из спутникового референса и проверить её на объёме в отдельном
worktree. Исходного снимка пользователя в репозитории не было; выбран главный корпус
«Жемчужины», уже присутствующий в срезе проекта как `w51847429`.

Результат: [`data/assets/zhemchuzhina/`](../../data/assets/zhemchuzhina/README.md).
Текстура создана встроенным `image_gen`, без CLI и без использования ключей проекта.
Точный запрос сохранён в [`generation-prompt.txt`](generation-prompt.txt).

## Запуск

Из корня worktree:

```sh
python3 work/building-texture/serve.py
```

Открыть http://127.0.0.1:8766/work/building-texture/preview.html.
Порт можно изменить через `--port`. Первый запуск скачивает закреплённый `@google/model-viewer`
4.4.0 в игнорируемую `.local/building-texture/`; потом просмотр работает без сети.
Это отдельный просмотрщик исходного GLB. Текстура также подключена к выбранному отелю в приложении:
`cd frontend && npm run dev -- --host 127.0.0.1 --port 5181 --strictPort`.
На http://127.0.0.1:5181/ используются текущие контуры и высоты API, а не геометрия этого GLB.

Пересобрать модель без сети и без генерации:

```sh
python3 work/building-texture/build.py
```

Сборщик намеренно ограничен одним полигоном без отверстий и этим атласом.
Он сохраняет все вершины исходного контура, разворачивает фасад непрерывно через коллинеарные
сегменты и триангулирует крышу отсечением ушей. Перенос на произвольные здания не реализован.

## Проверки и ограничения

- `validation.json`: отчёт Khronos Validator, ноль ошибок и предупреждений.
- `browser-check.json`: 8 сочетаний ширины 375/1440, RU/EN, светлой/тёмной темы.
- `preview-*.png`, `view-*.png`: локальные снимки экрана; исключены общим `.gitignore`.
- `source/`: референсы и сведения о запросе. Снимки исключены общим `.gitignore`;
  адреса источников и контрольные суммы находятся в `provenance.json`.

Выполнена проверка направления каждого треугольника относительно нормали, единичности нормалей
и UV в диапазоне [0, 1]. Модель открыта и осмотрена в Chromium на компьютере и мобильной ширине.
Для исходного GLB код приложения не менялся. При подключении к карте добавлены 7 тестов выбора
и геометрии, полный `npm run verify` прошёл на 320 тестах и 36 проверках правил.

Сырые спутниковые тайлы и фотография служат референсами. Фотограмметрия не запускалась:
нет набора перекрывающихся кадров с известной геометрией камеры. Видимая этажность текстуры
не является проверкой тега OSM. 51 м — допущение для визуализации.

Промежуточные неудачи: Python urllib не доверяет локальному набору CA; загрузка через curl
прошла с проверкой сертификата. ArcGIS export вернул пустой href и нулевой размер изображения;
использованы настоящие тайлы. Impeccable context не стартовал из-за относительного пути из
frontend; PRODUCT.md, DESIGN.md и применимые руководства прочитаны напрямую.

## Направление просмотрщика

Режим Experience: модель занимает основную область, справа — происхождение, ограничения и сам атлас.
Используются существующие токены Factmap, без изменения дизайн-системы. RU по умолчанию, EN,
светлая и тёмная темы. Переключатели ракурса доступны с клавиатуры; автоматического вращения нет.
Завершение: осмотр desktop/mobile, все ракурсы доступны, ограничения видны, артефакты сохранены.

## Подключение к карте

Текущая задача пользователя: «сделай 3д натягивание текстуры только на отель который отображаешь
в ./ работай в отдельном worktree». Результат находится в том же отдельном worktree на ветке
`feat/satellite-building-texture`. Исходный checkout с незавершёнными изменениями backend не менялся.

В `frontend/src/shared/geo/textured-building/` находятся отбор контуров, построение геометрии,
материал и пользовательский WebGL2-слой MapLibre. Hook в `features/hotel-map/texture/` управляет
загрузкой, выбором, стандартным объёмом при сбоях и освобождением GPU. Добавлен только Earcut
и его типы; Three.js и отдельный движок сцены приложению не нужны.

Материал `frontend/public/textures/hotel-albedo-v1.jpg` получен из исходного атласа конвертацией
JPEG quality 88, размер 1254 × 1254; точный промпт внедрён в JPEG COM. Растр загружается один раз
через TanStack Query. Полноценные PBR-карты и восстановление настоящих фасадов каждого отеля
не реализованы; материал подписан как условный. Показанные корпуса и их высоты приходят из API.

`node work/building-texture/verify-map.mjs` проверяет приложение на живом API через сохранённый
диалог, без новых платных модельных вызовов. Нужны работающий backend и указанный сохранённый
диалог; для другого стенда задать `TEXTURE_BASE_URL` и `TEXTURE_CONVERSATION_ID`.
Отчёт — `map-browser-check.json`, снимки — `map-*.png`. Проверены два реальных отеля:
`n11035837905` («шарм гостиница») и `n10759614195` (Golden Tennis Club).
WebGL-вызовы инструментируются только в браузерном тесте: один живой текстурный GL-program
после выбора, ноль после снятия, освобождение прежней программы после смены отеля.
Отдельно проверены 404 изображения, отказ компиляции, поздняя загрузка и восстановление контекста.

Ограничения: крыша плоская; обычные соседние здания сохраняют прежний вид; исходный GLB остаётся
отдельным примером на 51 м. На карте «Жемчужина» получает API-высоту 54,4 м. Данные геометрии
и условные детали изображения не смешиваются с фактами об отеле.

Итоговое независимое ревью: `ship` для этого расширения карты; [отчёт](finish-review.md).
Проверка production bundle на `http://127.0.0.1:5182/` сохранена в `map-production-check.json`.
Проверены реальный GPU draw, снятие выбора и совпадение SHA-256 выданного JPEG с исходным.
Два ранних кадра и production-кадр потребовали пересъёмки после загрузки карты; исправленные
снимки осмотрены. Система дизайна сохранена; документер не вносил изменений в DESIGN.md.
