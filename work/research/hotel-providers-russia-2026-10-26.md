# Источники данных об отелях России и сопоставление каталогов

Дата проверки: 26 октября 2026 года. Проверены публичные официальные документации и сайты поставщиков. Запросы с API-ключами, регистрации, заявки, обращения к менеджерам и платные вызовы не выполнялись. Стенд и модель не запускались.

## Вывод для реализации

Подтверждённого публичного API со всеми без исключения отелями России и полной информацией о каждом номере не найдено. «Все отели» в документации означает доступный каталог конкретного поставщика; это не доказательство национальной полноты. Полноту нужно измерять на нашем списке OSM и отдельной контрольной выборке.

Первое практическое действие — сопоставлять существующие локальные отели с уже подключённым Nuitee: искать кандидатов вокруг координат, дополнительно сужать по названию, проверять адрес, затем получать карточку по supplier ID. Для следующего российского источника подходят Яндекс Путешествия (REST, статический feed) и Bronevik (ежедневный каталог, значительное заявленное покрытие РФ). ETG/Островок также предоставляет современный Content API с фильтром по стране, то есть не обязательно скачивать весь мировой каталог. Это инженерная рекомендация по изученным интерфейсам, а не результат измерения покрытия.

## Сравнение назначений и барьеров

| Источник | Что можно получить | Сопоставление с нашим отелем | Доступ и ограничение |
|---|---|---|---|
| Nuitee / LiteAPI | Карточка, удобства, фотографии; отдельный поиск цен/доступности | Георадиус + название → supplier ID → detail | Ключ уже используется в проекте; покрытие РФ не установлено |
| Яндекс Путешествия, API партнёрской сети | Статический каталог, удобства, рейтинги; номера и цены отдельно | Локальный поиск по feed: названия, адреса, координаты | Партнёрство, добавление логина в White Label и OAuth |
| Bronevik | Ежедневный каталог доступных объектов, фото, предложения | Каталог или поиск по координатам/радиусу | NDA, тестовая интеграция, договор; SOAP/XML |
| ETG / Островок | Каталог, услуги, политики, категории; предложения отдельно | Content API по стране или dump, затем локальное сопоставление | Партнёрские ключи; доступ и сертификация; ограничения индексирования |
| TravelLine | Контент подключённых объектов, категории, тарифы, доступность | Перебор доступных property ID и адресов/координат | Партнёрство либо полномочия отдельного отеля; Search API связан с бронированием |
| 2ГИС Places | Название, адрес, координаты, атрибуты и контакты | Поиск по адресу, названию и георадиусу | Ключ/подписка, часть полей отдельно; это POI, а не наличие номеров |
| Яндекс Поиск по организациям | Адрес, координаты, сайт, контакты, некоторые особенности | Текст названия + адрес, область поиска | Ключ и условия использования; выдача по релевантности, не полная выгрузка |
| Росаккредитация | Официальная идентичность и статус записи реестра | Идентификатор записи и сверка карточки | Публичная витрина есть, документированный открытый API в этой проверке не подтверждён |
| 101Hotels | Отели РФ и коммерческие предложения | Схема API публично не проверена | Партнёрская заявка; заявлен порог аудитории для сайтов |

Утверждения матрицы раскрыты с источниками ниже. Возможность получить отельную карточку не означает возможность подтвердить доступный номер на даты, его реальный этаж, ориентацию окон или вид.

## Уже подключённый Nuitee: сначала использовать его каталог

Официальный `GET https://api.liteapi.travel/v3.0/data/hotels` принимает `countryCode`, `cityName`, `hotelName`, координаты и `radius`; имя сопоставляется неточно, без учёта регистра. Есть `offset`, `limit` (по умолчанию 200, максимум 5000), `lastUpdatedAt`. Минимальный георадиус — 1000 м. Адрес как отдельный параметр запроса не перечислен: его надо проверять в возвращённой карточке кандидата. Это позволяет искать конкретный отель по имеющимся координатам и названию, не зашивая 15 заранее выбранных соответствий. [Список отелей LiteAPI](https://docs.liteapi.travel/reference/get_data-hotels).

Далее `GET /v3.0/data/hotel?hotelId=...` возвращает описание, удобства, фотографии, адрес, координаты и классификацию. [Hotel Details](https://docs.liteapi.travel/reference/get_data-hotel). Номера с ценами и доступностью запрашиваются отдельно через `POST /hotels/rates`, с датами и составом гостей. [Rates](https://docs.liteapi.travel/reference/post_hotels-rates).

Официальный FAQ указывает бесплатные основные booking/management endpoints, но отдельно оплачиваемые premium-функции; производственный ключ требует платёжной настройки. Документация содержит противоречивые сведения о wallet, поэтому конкретный способ оплаты надо сверять с кабинетом. Не считать весь API бесплатным. [FAQ](https://docs.liteapi.travel/docs/faq). Sandbox предназначен для симулированного бронирования. Его доступность не подтверждает реальный российский инвентарь. [Sandbox booking](https://docs.liteapi.travel/docs/booking-a-room).

В изученных первичных источниках не найдено ни гарантии полного покрытия России, ни подтверждения общего запрета RU-отелей. Пустой ответ нельзя автоматически объяснять санкциями, отсутствием отеля или отсутствием мест: причины нужно различать по методу, среде и ответу API.

## Яндекс Путешествия: удобный российский каталог для локального связывания

Документация говорит о получении всех отелей **базы Яндекс Путешествий**, не всех отелей РФ. [Введение](https://yandex.ru/dev/travel-partners-api/doc/ru/).

`GET https://whitelabel.travel.yandex-net.ru/feeds/hotels/temporary_url` с `Authorization: OAuth ...` выдаёт временную ссылку на `.gz`, внутри построчные JSON-записи. Есть `hotel_id`, локализованные названия, компонентные и полные адреса, `country_code`, `lat`, `lon`, тип, звёзды, рейтинг, особенности/удобства и изображения. Цены и наличие в feed отсутствуют и запрашиваются отдельно. Это прямо подходит для загрузки RU-среза и локального сопоставления OSM по адресу и координатам. [Статический список отелей](https://yandex.ru/dev/travel-partners-api/doc/ru/feed-api).

`hotels/suggest` ищет отели и регионы по тексту; `hotels/hotel` получает карточку по ID; отдельные методы дают фотографии, отзывы, номера и цены. [Методы](https://yandex.ru/dev/travel-partners-api/doc/ru/methods). Карточка содержит адрес, координаты и группы удобств. [Hotel](https://yandex.ru/dev/travel-partners-api/doc/ru/hotel).

Для доступа нужно стать партнёром, согласовать добавление логина в White Label и получить OAuth-токен. Самостоятельный Yandex Cloud API-ключ не заменяет этот токен. Страница быстрого старта не обещает мгновенного свободного доступа к каталогу без партнёрства. [Подключение](https://yandex.ru/dev/travel-partners-api/doc/ru/getting-started).

Не путать этот API с `unisearch-hotels-pacific-partner-api.yandex.ru`: последний предназначен для передачи **наших** отелей/предложений в поиск Яндекса, а не для приобретения стороннего каталога. [Webmaster API для агрегаторов](https://www.yandex.ru/support/webmaster/en/search-appearance/hotels/about).

## Bronevik: российское покрытие и партнёрский коммерческий доступ

Bronevik заявляет 100 000+ объектов в России, 2000+ в соседних странах, 6000 населённых пунктов и ежедневное обновление данных. Это сведения поставщика на дату чтения, не независимый подсчёт и не доказательство наличия всех отелей. На той же странице FAQ говорит о доступе к 80 000+ объектов после договора; расхождение внутри страницы не разрешено. [Страница партнёров](https://bronevik.com/ru/partners).

Официальная страница API описывает XML/SOAP, ежедневный дамп доступных объектов, фотографии из CDN, тарифы и дополнительные услуги. Порядок: заявка → NDA → документация → тестовое окружение → договор → production. Поисковые запросы по умолчанию ограничены 5 RPS, условия можно согласовать. API не является открытым бесплатным национальным реестром. [API-интеграция](https://bronevik.com/ru/api-solutions).

Официальный репозиторий `bronevik-com/hotels-connector` показывает поиск по городу, ID отелей и координатам с радиусом до 30 км. Он ссылается на PDF API v2.5.2. Перед новой интеграцией актуальную версию и разрешённое хранение контента надо подтвердить в выданной документации, а не брать версию старого PHP-коннектора за текущую спецификацию договора. [Официальный коннектор](https://github.com/bronevik-com/hotels-connector).

## ETG / Островок: есть путь без мирового дампа

`POST https://api.ostrovok.ru/api/content/v1/hotel_ids_by_filter/` возвращает ID по фильтрам, в том числе `country` и `updated_since`. Страна — числовое значение из `Retrieve filter values`, не ISO `RU` и не пример `153` из документации. Метод рекомендован вместо hotel dump, ограничен 60 QPM. Далее используется `Retrieve hotels content by IDs`. Разрешения существующего ключа на Content API требуется проверить отдельно, без предположения, что любой B2B-ключ даёт этот доступ. [Фильтрация ID](https://docs-api.ostrovok.ru/docs/content-api/retrieve-hotel-ids-by-filter/), [контент по ID](https://docs-api.ostrovok.ru/docs/content-api/retrieve-hotels-content-by-ids/).

Альтернатива — полный `hotel/info/dump/`: Zstd, недельное обновление, временная ссылка на час; incremental dump обновляет статику за сутки. Официальная страница запрещает индексировать внутренний контент, включая фото и описания, но разрешает публичные название, адрес, удобства и политики. Нельзя автоматически отправлять весь дамп в наш векторный индекс. [Дамп и ограничения](https://docs-api.ostrovok.ru/docs/b2b-api/static-content/retrieve-hotel-dump/), [порядок синхронизации](https://docs-api.ostrovok.ru/docs/integration-guide/).

Карточка отеля содержит название, координаты, удобства, политики и категории. [Hotel content](https://docs-api.ostrovok.ru/docs/b2b-api/static-content/retrieve-hotel-content/). Ключи получают через партнёрское подключение, production — после интеграции и сертификации. [Получение ключей](https://help.b2b.ostrovok.ru/ru/articles/9330513). У ETG sandbox есть ограниченный набор demo-отелей, test-ключи не подтверждают доступность реальных отелей. Это описание ETG-сред; у Островок отдельная страница авторизации называет другие test ID, поэтому не переносить тестовые идентификаторы между продуктами. [ETG integration requirements](https://docs.emergingtravel.com/docs/best-practices-for-apiv3/), [Островок: авторизация](https://docs-api.ostrovok.ru/docs/fundamentals/authorization/).

## TravelLine: контент детальнее, но доступ определяется подключением

Content API даёт отели, категории, оснащение номеров, тарифы и услуги. `/api/content/v1/properties?include=All` поддерживает постраничное перечисление (до 200 за ответ); есть карточка по property ID. Доступ выдается либо отельером для его объекта, либо прямому партнёру. OAuth client credentials, access token на 15 минут. Search API требует использовать результаты для создания бронирований в TravelLine; простое извлечение данных без такого сценария не соответствует опубликованному условию. [Документация Partner API](https://www.travelline.ru/dev-portal/docs/api/).

Партнёрская страница заявляет 12 000+ отелей, передающих данные в каналы, а не все объекты РФ. Публикуются платное подключение, комиссии и минимальная стоимость; цены не являются публичной офертой. Для хакатона это не быстрый бесплатный источник. [Партнёрство](https://www.travelline.ru/about/technical-partners/partnership/).

**Инженерный вывод:** хороший кандидат для подтверждённого контента отдельных подключённых отельеров; слабее как первый источник национального каталога без уже выданных прав.

## POI-сервисы дополняют идентичность и контакты

2ГИС Places ищет по адресу, названию, координатам/радиусу, ID, телефону, сайту, ИНН и ФИАС. Работает с активными объектами. Ключи дают через demo/подписку; контакты, этажность, ФИАС и некоторые специальные методы отдельно согласуются и оплачиваются. Это подходит для кандидатов, контактов и части свойств здания, но не доказывает номера/тарифы отеля. [Places API](https://docs.2gis.com/api/search/places/overview). Права на постоянную загрузку POI в собственную БД и выбранные поля нужно согласовать в рамках подписки; документация о поиске сама по себе не даёт такого разрешения.

Яндекс Поиск по организациям принимает текст с названием/адресом и геообласть; даёт адрес, координаты, сайт, телефоны, часы и некоторые особенности. [Запрос](https://yandex.ru/maps-api/docs/geosearch-api/request.html), [ответ](https://yandex.ru/maps-api/docs/geosearch-api/response.html). Выдача упорядочена по релевантности и ограничена; это не полная национальная выгрузка. [Назначение и ограничения](https://yandex.ru/maps-api/docs/common/search/geosearch-api.html). Не считать ключ Yandex Cloud ключом Maps/Geosearch и не подменять справочные свойства доступностью отельных номеров.

## Реестр Росаккредитации и ещё два варианта

Официальная витрина: [Гостеприимство, средства размещения](https://tourism.fsa.gov.ru/ru/resorts/showcase/hotels). Прямое открытие официального портала через web-инструмент и Python HTTPS в этой проверке завершилось таймаутом/URLError. Доступность самого сервиса для пользователя из этого не следует. Публичная актуальная спецификация открытого API, условия массовой выгрузки и полнота полей не подтверждены. Не обещать готовый API. Этот источник следует рассматривать для идентификатора/статуса записи, а не цен и свободных номеров. Наличие поля реестра можно получать у поставщика: например, официальная документация Библио-Глобуса описывает для RU `idFGIS`, `stFGIS`, `sertFGIS`. [Библио-Глобус: справочники](https://export.bgoperator.ru/).

101Hotels официально предлагает полноценный API и заявляет прямые договоры с 35 000 отелей России. Программа адресована агентствам и сайтам с 10 000+ пользователей в день; доступ запрашивается у компании. Опубликованная страница не доказывает наличие открытого sandbox или конкретного метода адресного поиска. [Партнёрская программа](https://m.101hotels.com/partner_program).

Библио-Глобус публикует JSON-справочник отелей, вариантов размещения и питания, с привязкой к стране/городу и реестровыми полями для RU. В API предусмотрена авторизация агентскими логином/паролем; по умолчанию в списке только объекты с действующими ценами. Это потенциальный дополнительный нишевой источник, не полный национальный каталог. [Официальная документация](https://export.bgoperator.ru/).

## Предлагаемый контракт сопоставления

Ниже — рекомендации для реализации, а не обещания сторонних API.

1. Локальная карточка передаёт название, адрес, координаты, город/регион, а при наличии — телефон, сайт и реестровый номер.
2. Проверенное сохранённое соответствие поставщику используется первым. Иначе получаем ограниченный список кандидатов по георадиусу, названию или локальному импортированному каталогу.
3. Нормализуем регистр, `ё/е`, сокращения адресов, транслитерацию. Номер дома, корпус и строение сравниваем отдельно. Не выкидываем значащие части адреса ради нечёткого совпадения.
4. Близость координат — условие отбора кандидатов, не доказательство идентичности. Нельзя связывать соседние корпуса, разные отели по одному адресу и одноимённые отели в разных городах только по имени/расстоянию.
5. Результат: `matched`, `ambiguous`, `not_found`, `provider_unavailable`; для match храним supplier ID, исходные признаки, источник, дату и основание. Неуверенные пары не закрепляем как подтверждённые.
6. Статический контент и наличие номеров разделяем: при match получаем описание/удобства, а при заданных датах отдельно цены/доступность. Отсутствие предложения не удаляет отель из каталога.
7. Источники не затирают друг друга: каждый факт сохраняет supplier, дату и провенанс. Отсутствие поля не равно отрицательному свойству.
8. Кешируем результат и отрицательный поиск с ограниченным TTL, объединяем одновременные запросы для одного отеля. Не выполняем национальную синхронизацию при клике в карточку.

## Что проверять перед утверждением покрытия

Зафиксировать выборку до внешних запросов: города, регионы, разные типы объектов, небольшие отели и сетевые, близкие одноимённые кандидаты. Считать отдельно найденный каталогом объект, уверенную идентичность, наличие удобств, категорий номеров и предложений на даты. Все доли публиковать с числом объектов, датой, средой и поставщиком; ошибки/неоднозначности включать в знаменатель. Поскольку внешние запросы с ключом здесь не выполнялись, количественный результат покрытия отсутствует.

## Решение по очередности

- Сейчас: динамическое сопоставление через существующий Nuitee, без платного вызова при разработке; транспорт проверять зафиксированными ответами.
- Для российского каталога: получить доступ к API партнёрской сети Яндекс Путешествий или Bronevik; оба документируют выгрузку. Заявки сами не отправлялись.
