# Бесплатные источники данных об отелях России

Проверено 26 октября 2026 года по официальным источникам. Запросы с ключами, платные API, создание аккаунтов и обращения к поставщикам не выполнялись. Ограничение пользователя: источники информации должны работать бесплатно. Здесь речь об отсутствии платы за данные/запросы, а не об отсутствии собственных расходов на сервер, диск и сеть.

## Что использовать по умолчанию

| Источник | Плата/ключ | Что даёт | Предел |
|---|---|---|---|
| Уже загруженный OSM России / Geofabrik | Бесплатные открытые данные, без ключа | Название, адрес, координаты, теги, сайт, контакты, иногда комнаты/кровати | Нет гарантии всех отелей и заполненных полей |
| Wikidata | Публичные интерфейсы без платёжной настройки, CC0 для структурированных данных | Идентичность, координаты, официальный сайт, отдельные характеристики и внешние ID | Многие небольшие отели отсутствуют; часть утверждений без источника |
| Публичный официальный сайт конкретного отеля | Обычный HTTP без API-подписки; если страница доступна публично | Адрес, контакты, удобства, категории номеров; иногда JSON-LD | Разметка есть не везде; описание не равно живой доступности |

Рекомендация: локальные OSM-данные → официальный сайт из OSM/Wikidata → извлечение опубликованных структурированных полей с URL и датой. При нехватке информации показывать неизвестность. Не переключаться автоматически на платный API, платный поиск или платную модель.

Ни один проверенный бесплатный источник не гарантирует все отели России, полную инвентаризацию номеров и текущие цены.

## OSM и Geofabrik: бесплатный национальный срез уже существует

Geofabrik прямо называет публичную выгрузку бесплатной; данные обычно обновляются ежедневно. [Сервер выгрузок](https://download.geofabrik.de/). Файл России содержит OSM-данные всей России; на дату проверки страница показывает 3,9 ГБ и срез до 2026-10-25T21:21:21Z. Это размер опубликованного файла, не локальной базы и не прогноз затрат на импорт. [Россия](https://download.geofabrik.de/russia.html).

Для `tourism=hotel` документированы полезные сочетания `name`, `operator`, `addr:*`, `website`, `rooms`, `beds`. [Тег отеля](https://wiki.openstreetmap.org/wiki/Tag:tourism%3Dhotel). `website` предназначен для официального сайта объекта; также используется `contact:website`. [Website](https://wiki.openstreetmap.org/wiki/Key:website). Значения требуют проверки: база редактируется сообществом, старые и ошибочные ссылки возможны.

OSM распространяется под ODbL с атрибуцией и условиями для производных баз. Бесплатность не отменяет лицензию. [Лицензия](https://www.openstreetmap.org/copyright).

Для нашего масштаба следует искать по собственной PostGIS-базе, а не обходить публичный геокодер. Публичный Nominatim запрещает систематическую выгрузку всех POI; максимум обычных запросов — 1/с на приложение, нужны идентифицирующий User-Agent, кеш и атрибуция. Для регулярных/длительных задач ограничения строже. Этот сервис не предлагается как механизм массового обогащения. [Политика Nominatim](https://operations.osmfoundation.org/policies/nominatim/).

## Wikidata: бесплатное дополнительное сопоставление

Официальная документация публикует интерфейсы EntityData, Action API и SPARQL; они не требуют API-ключа для рассматриваемого чтения. `Special:EntityData/Q….json` возвращает известную сущность, `wbsearchentities` помогает найти ID, SPARQL — выбрать сущности по признакам. Для большой выгрузки рекомендованы dumps. Нужны информативный User-Agent, кеш, ограниченная параллельность и ожидание `Retry-After` при 429. [Data access](https://www.wikidata.org/wiki/Wikidata:Data_access). Структурированные данные имеют CC0. [Лицензирование](https://www.wikidata.org/wiki/Wikidata:Licensing).

Публичный SPARQL ограничен 60 секундами на запрос, 60 секундами обработки за минуту на клиента, 30 ошибочными запросами в минуту и пятью параллельными запросами на IP; пределы могут меняться. [Официальные лимиты](https://www.mediawiki.org/wiki/Wikidata_Query_Service/User_Manual#Query_limits). Сам публичный endpoint предоставлен для свободного использования; время ответа нестабильно. [Реализация WDQS](https://www.mediawiki.org/wiki/Wikidata_query_service/Implementation#Usage_constraints).

Пример: [Q2034313, московский «Метрополь»](https://www.wikidata.org/wiki/Q2034313) содержит координаты, официальный сайт, адрес/указания, этажность, число комнат и сторонние ID. Отдельные утверждения не имеют источника или опираются на старые сведения. Их нельзя безусловно считать актуальной инвентаризацией.

Практический порядок: использовать уже сохранённый OSM `wikidata` ID; если его нет — ограниченный поиск кандидатов, затем сравнить город, координаты и название. Не выбирать одноимённый объект только по первому результату. Для текущей карточки достаточно короткого запроса, национальную выборку не выполнять при клике.

## Официальные сайты: свойства без LLM и подписки

Schema.org определяет `Hotel` и поля адреса, координат, контактов, удобств, звёздности, времени заезда/выезда, домашних животных и числа комнат; пример содержит JSON-LD в `script[type="application/ld+json"]`. [Hotel](https://schema.org/Hotel). Схема различает отель, конкретную единицу размещения и предложение цены/условий. [Модель размещения](https://schema.org/docs/hotels.html). Наличие `amenityFeature` само по себе **не говорит**, включена ли услуга в тариф или оплачивается отдельно. [Семантика удобства](https://schema.org/amenityFeature).

Предлагаемый парсер без платной модели:

1. Взять сохранённый официальный URL из OSM/Wikidata, не конструировать домен из названия.
2. Получить ограниченный объём публичного HTML; учитывать ограничения сайта и `robots.txt`, кешировать, не обходить защиту/авторизацию.
3. Разобрать JSON-LD, включая массивы и `@graph`, и выбрать Hotel/LodgingBusiness по совпадению названия и фактического адреса/координат. Общий Organization не достаточен.
4. Сохранить исходный URL, время, путь поля и исходное значение. При ошибке или отсутствии разметки вернуть `unavailable`/пустой контент, а не выдумывать значения.
5. Не считать `priceRange` ценой на даты, `numberOfRooms` количеством свободных номеров, а фотографии или общую рекламу доказательством ориентации окна конкретного номера.

Официальный [сайт «Метрополя», контакты](https://metropol-moscow.ru/contacts/) раздельно указывает фактический и юридический адреса и реестровый номер; для сопоставления нужен фактический. [national.ru](https://www.national.ru/) — официальный источник «Националя». Для сравнения, [hotel-national.ru](https://hotel-national.ru/) прямо сообщает, что не является официальным сайтом. Последняя страница изучена только для проверки происхождения, не используется как источник гостиничных фактов.

Бесплатное публичное чтение страницы не подтверждает открытую лицензию на её тексты или фотографии. В этой проверке права на массовое копирование/перепубликацию материалов отелей не устанавливались. Для реализации следует отделять извлечённые фактические поля и ссылку на источник от копирования описаний и изображений, учитывать условия каждого сайта. `robots.txt` описывает правила автоматического доступа; это стандарт Robots Exclusion Protocol, а не лицензия или способ обхода авторизации. [RFC 9309](https://www.rfc-editor.org/rfc/rfc9309.html). Это требования к проектированию; исследование не подтверждает, что текущий загрузчик уже реализует все проверки.

Публичные тексты страниц прочитаны web-инструментом. Прямое получение HTML этих двух сайтов через Python в среде исследования завершилось `URLError`; наличие JSON-LD на них таким способом **не подтверждено**. Описанный формат подтверждён Schema.org; покрытие реальных сайтов остаётся предметом проверки реализации.

## Росаккредитация: бесплатная витрина не равна подтверждённому API

Официальная точка входа — [Гостеприимство, реестр](https://tourism.fsa.gov.ru/ru/resorts/showcase/hotels). Публичная документированная спецификация бесплатного API/выгрузки в этой проверке не найдена. Web-инструмент получал таймаут; Python HTTPS для портала и fsa.gov.ru дал `SSLCertVerificationError: self-signed certificate in certificate chain`. Это ограничение доступа из среды проверки, не вывод о недоступности портала для всех.

Не следует выдумывать стабильный endpoint из внутренних URL сайта и обещать полную бесплатную интеграцию. При наличии реестровой ссылки на сайте отеля можно сохранить её как источник официальной идентичности; цены и номера из неё не следуют.

## Nuitee: точная граница бесплатности

Официальный тариф прямо перечисляет Hotel content endpoints и прочие невыделенные методы как бесплатные. Основная цепочка Rates → Prebook → Book также бесплатна, **при соблюдении ToS и разумного отношения поисков к бронированиям**. Places стоит $0.01 за запрос, price index — $0.05; возможны изменение условий и пересмотр нестандартного использования. [API Pricing & Usage Costs](https://docs.liteapi.travel/reference/api-pricing-usage-costs).

Следовательно, неверно называть обычные `/data/hotels` и `/data/hotel` платными только потому, что они принадлежат Nuitee. Но неверно и обещать безусловно бесплатное массовое извлечение контента для продукта без бронирования: fair use остаётся условием. FAQ требует действующую карту для production-ключа; бесплатный аккаунт даёт sandbox. [FAQ](https://docs.liteapi.travel/docs/faq).

При требовании «всё бесплатно» и без платёжной настройки надёжный default — не выполнять коммерческие вызовы с сохранёнными ключами. Существующий адаптер можно оставить отключённым; бесплатные sandbox-данные не выдавать за подтверждённые реальные цены. Никаких автоматических обращений к Places, price index или платному резерву.

## Партнёрские API не следует автоматически считать платными

Bronevik требует NDA, тестирования и договора; публичная страница не устанавливает обязательную плату именно за API-запросы. [Порядок подключения](https://bronevik.com/ru/api-solutions). Яндекс Путешествия требует партнёрство/White Label/OAuth; страница быстрого старта не подтверждает ни платный тариф, ни безусловное бесплатное использование нашим проектом. [Подключение](https://yandex.ru/dev/travel-partners-api/doc/ru/getting-started).

Их статус для задачи — **цена и права использования не подтверждены**, а не «точно платные». Они исключаются из бесплатного runtime до подтверждения подходящих нулевых условий. Заявки и переговоры не выполнялись.

## Что измерять дальше

Фиксировать отдельно количество OSM-отелей, имеющих website/contact:website/wikidata; количество успешно полученных официальных страниц; число идентифицированных карточек с JSON-LD; заполненность каждого поля. Полную отсутствующую инвентаризацию оставлять неизвестной. Публиковать размер выборки, дату и неуспешные запросы. Нулевую цену источника нельзя подменять обещанием полного покрытия.

## Передача в реализацию

По сообщению основного исполнителя, выбран `HOTEL_DATA_MODE=free` как режим по умолчанию: Nuitee/ETG отключены в runtime даже при наличии ключей, ручные match/sync-команды блокируются в этом режиме. Добавлен разбор JSON-LD Hotel/LodgingBusiness в существующий загрузчик публичных страниц; поля остаются недоверенным свидетельством до проверки принадлежности отелю. Эти изменения не исследовались повторно в данном worktree и не являются результатом внешней проверки покрытия.

Режим относится к источникам гостиничных данных. Ранее выбранные Claude и embeddings не меняются этим решением; запуск модели и стенда здесь не выполнялся. Парсер метаданных сам не требует платной модели или API-подписки.
