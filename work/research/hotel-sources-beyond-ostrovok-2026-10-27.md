# Источники данных по конкретному отелю помимо Островка

Проверено 27 октября 2026 года. Проверялись публичная документация, `robots.txt`, тарифные
страницы, публичные карточки объектов и схемы разметки. Регистрации, заявки поставщикам,
создание аккаунтов, платные вызовы и использование чужих ключей не выполнялись. HTTP-проверки
делались единичными запросами с паузами 2–3 секунды, без постраничного обхода; для каждой
проверки ниже указан точный URL, код ответа и дата. Локальные измерения по базе — один
read-only SQL к работающему контейнеру `hotel-agent-db-1`.

Задача: чем дополнить карточку, когда на Островке отель не находится или карточка пустая.
Что уже исследовано и здесь не повторяется: `work/research/free-hotel-data-2026-10-26.md`
(OSM/Geofabrik, Wikidata, официальные сайты и JSON-LD, граница бесплатности Nuitee),
`work/research/hotel-providers-russia-2026-10-26.md` (партнёрские API Яндекс Путешествий,
Bronevik, ETG, TravelLine, 2ГИС, 101Hotels), `work/research/hotel-inventory.md`,
`work/hotel-data/free-mode.md` (режим `HOTEL_DATA_MODE=free`).

## Что использовать первым fallback'ом после Островка

**101hotels.com — публичная карточка отеля.** Это единственный проверенный источник, который
в одном server-rendered HTML отдаёт почти тот же набор полей, что мы тянем из Островка, и
дополняет его двумя полями, которых нет больше нигде бесплатно: номер реестровой записи
федерального реестра и размер номерного фонда. На карточке
[«Бизнес-отель Кострома»](https://101hotels.com/main/cities/kostroma/gostinitsa__biznes_otel_kostroma.html)
(HTTP 200, 1 017 818 байт, 2026-10-27) присутствуют: микроразметка `schema.org/Hotel` с
`name`, `latitude`/`longitude` (57.769478 / 40.913662), `streetAddress`, `telephone`,
`priceRange`, `currenciesAccepted`; `schema.org/AggregateRating` со значением 9.1 и 1 018
отзывами плюс подоценки (расположение, обслуживание, цена/качество, чистота, питание);
`amenityFeature` как `LocationFeatureSpecification` с `name` и `value`; `ImageObject` с
подписями кадров и `creditText`; `FAQPage` с временем заезда и выезда (14:00 / 12:00);
в тексте — «Год открытия: 2011. Номерной фонд: 24 номера», расстояния до центра, аэропорта,
вокзала и реки, политика по животным; строка «Объект прошел государственную аккредитацию:
Номер реестровой записи: С442024016365». Категории номеров отрендерены без дат: блоки с
`data-room-id` содержат название, площадь (18 м²), тип кровати, вместимость, удобства и фото.
Встроенное состояние `window.hotelPageParams` даёт `hotelStars: '3'`, `hotelRating`,
`hotelMinPrice`, `hotelClassified: true` и внутренний `hotelId`.

Почему именно он первым: это те же действия, что уже реализованы для Островка (чтение
публичной страницы и разбор разметки), без ключей, партнёрства и платы; поля совпадают с нашей
моделью карточки; `robots.txt` не запрещает страницы отелей общему агенту. Ограничение —
цену на конкретные даты страница не отдаёт («Укажите дату, чтобы узнать стоимость»), а поиск
закрыт в `robots.txt`.

**Второй по приоритету — Alean.** Его публичная карточка содержит чистый JSON-LD `Hotel`
(в отличие от микроразметки 101hotels, разбирается без эвристик) и перекрывает тот сегмент,
где 101hotels слабее: санатории, пансионаты, курортные комплексы и малые населённые пункты.
Публичный `sitemap-hotels.xml` перечисляет 20 665 российских URL в 102 регионах, то есть это
не только Сочи и Москва.

Ни один из найденных источников не даёт ни полного национального списка, ни цены на даты
бесплатно. Для цен бесплатного fallback'а к Островку не найдено вообще.

## Федеральный реестр средств размещения (Росаккредитация)

Прошлая проверка упиралась в таймаут и `SSLCertVerificationError`. **27 октября 2026 года
портал доступен из этой среды.** `curl` к
[витрине средств размещения](https://tourism.fsa.gov.ru/ru/resorts/showcase/hotels) вернул
HTTP 200 (3,36 с, IP 212.164.138.20), `https://tourism.fsa.gov.ru/robots.txt` — HTTP 200 с
содержимым `User-agent: *` / `Allow: /` и ссылкой на sitemap. Старая страница реестра
`https://fsa.gov.ru/use-of-technology/elektronnye-reestryy/reestr-klassifitsirovannykh-obektov-gostinitsy-i-inye-sredstva-razmeshcheniya/`
отдаёт HTTP 301 именно на эту витрину — значит официальная точка входа подтверждена.

Это не даёт машинного доступа. Страница — Angular-приложение: после удаления `<script>`
текст `<body>` пуст, то есть ни списка, ни карточки в HTML нет. В `<head>` объявлено
`<meta name='hmac-token-name' content='Ajax-Token'/>`, то есть внутренние XHR-вызовы витрины
подписываются токеном. [Sitemap](https://tourism.fsa.gov.ru/sitemap.xml) перечисляет только
восемь разделов на язык (`/main`, три витрины, организации, эксперты, самооценка, новости) —
URL отдельных объектов в нём нет. Внутренние endpoints витрины я не документирую и не
предлагаю: они не опубликованы как интерфейс.

Открытые данные Росаккредитации существуют отдельно и реестра средств размещения **не
содержат**. [Раздел открытых данных](https://fsa.gov.ru/opendata/) (HTTP 200) сообщает:
«Общее количество наборов открытых данных: 12» и перечисляет их — территориальные органы,
вакансии, статистическая информация, аккредитованные лица, негосударственная экспертиза,
органы по сертификации, испытательные лаборатории, экспертные организации, госуслуги,
сертификаты соответствия, декларации о соответствии, зарегистрированные декларации.
Гостеприимства и средств размещения среди них нет; машиночитаемый реестр наборов —
[list.xml](https://fsa.gov.ru/opendata/list.xml). Условия этого раздела, если набор когда-то
появится, подходят нам идеально: «использовать (в том числе повторно) открытые данные
свободно, бесплатно, бессрочно, безвозмездно и без ограничения территории использования»,
разрешено копировать, видоизменять и использовать в коммерческих целях, обязанность —
«сохранять ссылку на источник информации».

Нормативное требование публичности реестра по постановлению Правительства РФ № 1952 от
27.12.2024 в этой проверке по официальному тексту **не подтверждено**: попытка обратиться к
`publication.pravo.gov.ru` по угаданному пути поиска вернула HTML-оболочку SPA, а не данные,
и дальше я не угадывал. Само постановление и его предмет подтверждаются только вторичными
публикациями, поэтому ссылка на конкретный пункт о общедоступности здесь не приводится.

Практический вывод. Реестр остаётся источником официальной категории и номера записи для
ручной проверки человеком, а не механизмом обогащения. При этом **номер реестровой записи
можно получить бесплатно из карточки 101hotels** (`С442024016365` в проверенном примере) и
дальше использовать как ключ официальной идентичности и как ссылку для проверки в витрине.
Это снимает прошлое ограничение «реестр недоступен» в практическом смысле, не выдумывая API.

Региональных выгрузок реестра в формате XLSX поиск не нашёл; это осталось непроверенным.
Федеральный портал `data.gov.ru` не отвечает: `curl: (6) Could not resolve host`.
`opendata.gov.ru` отдаёт самоподписанный сертификат (`curl: (60)`).

## 101hotels.com

`robots.txt` (7 295 байт, 2026-10-27) содержит отдельные блоки для Yandex, YandexDirect,
Bingbot (с `Crawl-delay: 8`), `ia_archiver` и ряда SEO-краулеров, а также общий блок
`User-agent: *`: запрещены `/opinions/city/*/*`, `/opinions/page/*`, `/?*`, `/search`,
`/city*`, `/redirect`, `/favorites`, `/nearby/location`, `/widget/generator/*`,
`/booking/order_form`, `/app*`, `/mobile_app`; явно разрешены `/opinions/city/`,
`/opinions/hotel/*/*.html` и `/opinions$`. Страницы `/main/cities/<город>/<объект>.html` и
`/main/cities/<город>` под запреты не попадают. `Sitemap` в файле не объявлен, а
`https://101hotels.com/sitemap.xml` отдаёт HTTP 404 — значит полного перечисления объектов
публично нет.

[Страница города](https://101hotels.com/main/cities/kostroma) (HTTP 200, 614 863 байта)
содержит 26 ссылок на карточки объектов и ту же микроразметку, что карточка: `Hotel`,
`GeoCoordinates`, `PostalAddress`, `AggregateRating`, `LocationFeatureSpecification`,
`BreadcrumbList`, `FAQPage`. То есть индексация по городам возможна без запрещённого поиска.
Блоков `application/ld+json` на страницах нет: разметка микроформатная, через `itemtype` и
`itemprop`, поэтому для разбора нужен парсер микроданных, а не только JSON-LD.

Состав полей карточки перечислен выше, в разделе «Что использовать первым fallback'ом».
Цена за даты требует закрытого в `robots.txt` поиска, поэтому её брать не следует;
публично доступна только `priceRange` вида «от 5 800 руб. средняя цена за номер, точную
стоимость смотрите на сайте по датам» — это не цена на даты и не должна так показываться.

Правовая сторона.
[Пользовательское соглашение](https://101hotels.com/page/contacts/polzovatelskoe_soglashenie)
прямого запрета на автоматизированный сбор, копирование или создание базы **не содержит**;
ближайшие формулировки общие: «Пользователь обязуется соблюдать законодательство РФ, а также
права и законные интересы третьих лиц» (п. 3.3) и аналогичный п. 3.10, сервис предоставляется
«как есть» (п. 3.1). Отсутствие запрета не равно открытой лицензии: фотографии в разметке
несут `creditText: 101Hotels.com`. Отсюда то же правило, что мы уже приняли для Островка:
извлекать фактические поля с сохранением URL и времени, показывать ссылку на источник, не
перепубликовывать описания и фотографии как свой контент.

Измерение покрытия, ограниченное и честное. В нашей базе 13 отелей с `addr:city = Кострома`
имеют осмысленное имя (одна запись — технический идентификатор `w177029101`). На одной
разрешённой странице города 101hotels нашлось 26 карточек; по названию совпали 7 из 13
(Александровский, Бизнес-отель Кострома, Волга, Островский причал, Берендеевка, Я-Отель,
Екатерина), не совпали Воскресенская, Золотое кольцо, МХостел, Хостел44, «17 Изба». Это
**не** оценка покрытия: страница отдаёт первую порцию списка, ссылок на пагинацию в HTML нет,
поиск использовать нельзя, сопоставление делалось только по имени. Отсутствие в этой выдаче
не доказывает отсутствия объекта на сайте. Для реальной цифры нужен отдельный замер с
фиксированной выборкой городов и правилом сопоставления, в том числе через страницу
`/main/cities/<город>/onmap`, которая правилами не запрещена и не проверялась.

Партнёрский API 101hotels остаётся закрытым путём: порог аудитории и заявка описаны в
прошлом исследовании (`work/research/hotel-providers-russia-2026-10-26.md`).

## Яндекс Путешествия: публичный сайт технически закрыт

`robots.txt` (4 401 байт) содержит блоки `Yandex`, `Googlebot` и `*`. В общем блоке запрещены
`/?*`, `/*/search*`, `/*/order*`, `*/book/*`, `*/booking/*`, `/api/`, `/extranet*`,
`/feeds/cost-plus/*`, `/amp/`; **страницы отелей в общем блоке не запрещены** (запрет
`*/hotel/*/*` стоит только в блоке `Yandex`), и объявлен
`Sitemap: https://travel.yandex.ru/sitemaps/hotels/sitemap.xml.gz`.

На практике это не работает. И запрос этого sitemap, и запрос
`https://travel.yandex.ru/hotels/moscow/metropol/` с браузерным User-Agent вернули **HTTP 302
на `https://travel.yandex.ru/showcaptcha?...`** с заголовком `x-yandex-captcha: captcha`
(2026-10-27). То есть публичные страницы Яндекс Путешествий недоступны автоматизированному
клиенту без решения капчи; обходить защиту мы не будем. Партнёрский API с OAuth и статическим
feed остаётся прежним вариантом с неподтверждёнными условиями — см.
`work/research/hotel-providers-russia-2026-10-26.md`.

`-k` сервер (IP 89.104.91.115) отдаёт `curl: (52) Empty reply from server`. `www.hotel.ru`
даёт ту же ошибку сертификата. Источник недоступен из этой среды 2026-10-27.

**Putevka.com.** `robots.txt` разрешает карточки, запрещает `/*?`, `/search`, `/tours/search`

## Движки бронирования на сайтах отелей

Идея была: определить виджет на официальном сайте отеля и взять номера и тарифы от отельера.
Проверка по официальным источникам показывает, что публично документированного чтения без
выданных прав нет ни у одного вендора.

**TravelLine** — единственный с публичной документацией.
[Partner API](https://www.travelline.ru/dev-portal/docs/api/) описывает
`GET /v1/properties` (отели с категориями номеров, тарифными планами и услугами),
`GET /v1/properties/{propertyId}`, правила отмены и дополнительного проживания, справочники
`/v1/room-type-categories`, `/v1/meal-plans`, `/v1/room-amenity-categories`, а поиск —
`POST /v1/properties/room-stays/search` и
`GET /api/search/v1/properties/{propertyId}/room-stays`. Авторизация — OAuth client
credentials на `https://partner.tlintegration.com/auth/token`, JWT живёт 15 минут и не
обновляется. Доступ выдаёт либо отельер («Отельер создает API-подключение в личном кабинете
TravelLine»), либо TravelLine прямому партнёру. Лимиты документированы: авторизация 3 rps /
15 в минуту / 300 в час на IP, обычные методы 50 rps / 200 в минуту / 3 000 в час, поиск
3 rps / 20 в минуту / 900 в час. Ключевое условие: «Обязательным условием предоставления
Search API является использование результатов поиска для создания бронирований», и API
«может быть отключено правообладателем в одностороннем порядке» при нарушении. Для продукта
без бронирования это прямо исключает использование Search API ради данных. Цена на странице
API не указана.

**Bnovo.** [bnovo.ru](https://bnovo.ru/) публичного API и портала для разработчиков не
документирует. Есть модуль бронирования `/bnovo-mb/`, раздел интеграций `/integration/`
(уборка, 1С, Bnovo Pay, iiko и другие) и база знаний `help.bnovo.ru` с инструкциями по
продукту. Тариф указан как «от 240 ₽» за номер, отдельной цены API нет. `docs.bnovo.ru`
не отвечает: `tlsv1 unrecognized name`.

**Frontdesk24.** [frontdesk24.ru](https://frontdesk24.ru/) (HTTP 200) не содержит ни
справочника API, ни endpoints, ни условий доступа: только разделы «Интеграции»,
«Channel Manager», «Модуль онлайн-бронирования» без технических деталей и контакты.

**Realty Calendar.** `https://realtycalendar.ru/` отдаёт HTTP 302 на
`https://new.realtycalendar.ru/`; дальше не проверялось. Остаётся непроверенным.

Практический остаток идеи: по сохранённому `website` можно определить, что отель вообще
продаёт номера напрямую (по хосту скрипта или iframe модуля на его странице), и это полезный
признак для карточки. Получить от движка номера и тарифы без выданных отельером реквизитов
нельзя.

## Travelpayouts / Hotellook

Официальная доступная спецификация — [travelpayouts.github.io/slate](https://travelpayouts.github.io/slate/)
(HTTP 200) — **отельных методов не содержит**: там Data Access API v1/v2 по авиа-ценам,
статические справочники (страны, города, аэропорты, авиакомпании, альянсы, самолёты,
маршруты) и авиапоиск. Из условий там подтверждается только общее: «To access the API you
must pass your token in the X-Access-Token header or in the token parameter», авиапоиск
подписывается `signature` из токена и маркера, лимит по умолчанию 200 запросов в час на IP,
ссылки результатов живут 15 минут, статические данные рекомендуется кешировать.

Отельная документация живёт на `support.travelpayouts.com` и из этой среды недоступна:
и статья `203956163`, и раздел `200239169` вернули **HTTP 403** с Cloudflare-челленджем
«Just a moment… Enable JavaScript and cookies to continue» (2026-10-27). Хосты
`docs.travelpayouts.com` и `developers.travelpayouts.com` отдают HTTP 404,
`api.travelpayouts.com` без токена — HTTP 401.

Следовательно: условия бесплатного партнёрского токена, состав отельных полей и покрытие РФ
по первоисточнику **не подтверждены**. Утверждения о «бесплатном токене сразу после
регистрации» и «список отелей одним файлом» встречаются только в собственном блоге
Travelpayouts и у сторонних обёрток — это вторичные источники, и как доказательство я их не
использую. Дополнительно: доступ требует регистрации в партнёрской программе, что выходит за
рамки этой задачи. Отдельно стоит учитывать, что Hotellook — метапоиск, который среди прочих
показывает те же предложения Островка, то есть прироста покрытия по России он может и не
дать; это тоже не проверено.

## Карты и справочники организаций

**2ГИС Places API.** [Обзор](https://docs.2gis.com/en/api/search/places/overview) прямо
говорит: «Create a demo key or purchase a subscription for using API», тарификация — за
успешный запрос с `meta.code` 200, а контакты (`items.contact_groups`) и этажность
(`items.floors`, `items.floor_plans`) отнесены к платным полям «on demand».
[Страница цен](https://docs.2gis.com/en/platform-manager/subscription/pricing) даёт конкретику:
demo-ключ — всего 1 000 запросов к Places, пакеты от 6 700 ₽ за 10 000 запросов до
250 000 ₽ за 5 000 000, лимит 600 единиц в минуту, скидка 10 % при годовой подписке. Для
постоянного обогащения 34 тысяч карточек это платный источник; как разовая проверка
идентичности и контактов для нескольких отелей demo-ключа может хватить, но права на
постоянное хранение полей нужно согласовывать отдельно.

**Яндекс Карты, Геопоиск и Геокодер — исключаются по условиям, а не по цене.**
[Условия использования API Яндекс Карт](https://yandex.ru/legal/maps_api/) содержат прямые
запреты, несовместимые с нашей моделью: п. 5.1.6 запрещает «Сохранять, обрабатывать и
видоизменять полученные через Сервисы Данные», допуская только временное кеширование «на
срок не более 30 дней» и «исключительно для целей улучшения функциональности и
работоспособности Сервисов»; п. 6.6.1 — «Пользователю запрещается отображать результаты
работы Геокодера в сервисах третьих лиц»; п. 5.1.4 запрещает создавать сервисы,
«функциональное и целевое назначение которых аналогично или схоже с сервисом «Яндекс
Карты»»; п. 7.3 закрепляет права на базу данных, созданную с использованием Сервисов, за
Яндексом; п. 4.1.1 ограничивает бесплатное использование бесплатными общедоступными сайтами
и приложениями, «Сервисы не могут использоваться в проектах, требующих оплаты». Лимиты:
Геокодер — 1 000 запросов в сутки (п. 6.6.2), Static API — 100 в сутки (п. 6.3.1), у
Геопоиска [документация](https://yandex.ru/maps-api/docs/geosearch-api/index.html) указывает
«Количество запросов в секунду (RPS): до 50». Для источника фактов карточки, которые мы
храним и показываем с доказательствами, это не подходит.

**OpenTripMap.** [Продукт](https://dev.opentripmap.org/product) собран из открытых данных:
OpenStreetMap, Wikidata, Wikipedia, `all.culture.ru`, Минприроды; лицензия заявлена как ODbL,
объём — «over 10 million tourist attractions and facilities». [Тариф](https://dev.opentripmap.org/price):
Free, $0 в месяц, 5 000 запросов в сутки, 10 rps, «Non-commercial use». Размещение как класс
объектов на странице продукта не упомянуто. Поскольку это производное от OSM и Wikidata,
которые у нас уже есть локально, прироста по отелям ждать не стоит, а оговорка
non-commercial делает его неподходящим для продукта.

**Wikivoyage.** Русская Викигидия публикуется под CC BY-SA: в футере страницы
[Кострома](https://ru.wikivoyage.org/wiki/Кострома) прямо написано «Текст доступен по
лицензии Creative Commons «С указанием авторства — С сохранением условий» (CC BY-SA)».
Страница содержит 81 блок `vcard` с классами `listing-name`, `geo`, `tel` — то есть listing-и
разбираются машинно. Но это рукописные записи туристического путеводителя: полнота,
актуальность и наличие нужных нам полей не гарантированы. Годится как дополнительный
источник названия, адреса и телефона, не как карточка.

**Wikimedia Commons.** [Commons:Licensing](https://commons.wikimedia.org/wiki/Commons:Licensing)
требует, чтобы каждый файл был «explicitly freely licensed» или в общественном достоянии,
лицензия должна разрешать перепубликацию, производные и коммерческое использование и быть
«perpetual (non-expiring) and non-revocable»; файлы только под non-commercial лицензиями не
принимаются; «it is the responsibility of reusers to ensure that the use of the media is
according to the license», атрибуция может быть обязательной. Это единственный источник
фотографий с ясным правом на показ, но он покрывает только известные объекты.

органы публикуют по ней сводки в PDF (например, в медиабанках `33.rosstat.gov.ru` и

Колонка `hotels.stars` заполнена у 1 178 записей. Семантика тегов подтверждается вики:
[`rooms`](https://wiki.openstreetmap.org/wiki/Key:rooms) — «Amount of rooms available for
guests», `beds` — число кроватей, `capacity` зависит от типа объекта;
[`stars`](https://wiki.openstreetmap.org/wiki/Key:stars) имеет статус de facto и по правилам
должен ставиться только по звёздам от признанных туристических органов, а не по субъективным
рейтингам. Вывод: OSM задаёт идентичность и адрес, но ни звёзды, ни номерной фонд, ни
этажность из него получить массово нельзя, и у трёх четвертей отелей нет даже ссылки на сайт.
Именно поэтому нужен внешний fallback по имени и координатам, а не обогащение тегами.

**Wikidata.** Свойства для номера реестровой записи российского реестра средств размещения
**не существует**: поиск свойств через `wbsearchentities` (`type=property`, `language=ru`) по
«реестр», «гостиниц», «классификация» не дал ни одного релевантного результата (2026-10-27).
Есть `P10290 hotel rating` (звёзды) и идентификаторы зарубежных ОТА: `P3898` Hotels.com,
`P5651` Expedia, `P6008` Agoda, `P10425` Trip.com, `P10547` Kayak — они пригодны как
перекрёстные ссылки, но для России малополезны. С учётом 145 отелей с тегом `wikidata`
источник остаётся точечным.

## Что осталось непроверенным

- Нормативное требование общедоступности единого реестра по официальному тексту
  постановления № 1952 от 27.12.2024: угаданный путь поиска на `publication.pravo.gov.ru`
  вернул HTML SPA, дальше не угадывал.
- Региональные выгрузки реестра классифицированных средств размещения (XLSX на сайтах
  региональных министерств туризма): поиск ничего конкретного не дал, адресно не проверялось.
- Условия Travelpayouts/Hotellook по отелям: официальная документация закрыта Cloudflare
  (HTTP 403).
- Realty Calendar: только редирект на `new.realtycalendar.ru`, API не проверялся.
- Карточки Onetwotrip и Level.travel: прочитаны только `robots.txt`.
- Региональные сводки Росстата по форме 1-КСР и показатели ЕМИСС: файлы не открылись из-за
  ошибки проверки сертификата, конкретные индикаторы ЕМИСС адресно не искались.
- Карточка отдельного объекта на Putevka.com и на Bronevik.com: не открывалась (у Bronevik
  URL карточек публично не перечислены).
- Реальное покрытие 101hotels и Alean по нашему списку: нужен отдельный замер с фиксированной
  выборкой городов, правилом сопоставления по имени, адресу и координатам и раздельным учётом
  `matched` / `ambiguous` / `not_found`. Проверка по Костроме выше — единичная и не является
  оценкой покрытия.
- Страница `/main/cities/<город>/onmap` у 101hotels как способ получить полный список города:
  правилами не запрещена, не проверялась.
- Правовая оценка систематического чтения публичных карточек 101hotels и Alean: соглашения
  прямого запрета не содержат, но открытой лицензии тоже нет; это решение о риске, а не
  установленный факт.
- Устойчивость разметки: микроданные 101hotels и JSON-LD Alean проверены на одной карточке
  каждый. Варианты вёрстки для санаториев, хостелов и апартаментов не проверялись.

## Рекомендуемая цепочка для карточки отеля

1. Островок, публичная карточка — как сейчас. Если нашлась и непуста, остальное не трогаем.
2. **101hotels.com.** Сопоставление: по городу берём разрешённую страницу `/main/cities/<город>`,
   из микроразметки собираем кандидатов с `latitude`/`longitude`, `streetAddress` и `name`,
   отбираем по расстоянию и названию, затем читаем карточку объекта. Из неё берём звёзды,
   номер реестровой записи, номерной фонд, год открытия, удобства, категории номеров с
   площадью и кроватями, рейтинг с подоценками и числом отзывов, заезд/выезд, политику по
   животным, расстояния, фото с подписями. Поиск сайта не использовать — запрещён в robots.txt.
3. **Alean.** Применять, когда 101hotels не дал карточку, и всегда для санаториев, пансионатов
   и курортных комплексов. URL объектов берём из публичного `sitemap-hotels.xml`, сопоставляем
   по региону, городу, названию и координатам из JSON-LD. Берём `starRating`, адрес с индексом,
   координаты, `amenityFeature`, питание, заезд/выезд, животных, инфраструктуру; число номеров
   извлекаем из описания с пометкой «из текста».
4. **Официальный сайт отеля** из OSM `website` с разбором JSON-LD — уже реализовано. Это
   единственный источник того, что утверждает сам отель, и единственный способ получить
   контакты для 24 % отелей, у которых ссылка есть.
5. **Витрина Росаккредитации** — для человека: проверить официальную категорию и статус записи
   по номеру, полученному на шаге 2. Машинной выгрузки нет, в автоматический контур не ставить.
6. **OSM и Wikidata** — базовая идентичность и то немногое, что измерено выше. Wikidata
   применять только при наличии тега (0,4 % отелей).

Каждое поле сохраняем с источником, URL и временем получения, как уже принято для Островка.
Источники не затирают друг друга; расхождение звёзд или числа номеров между 101hotels, Alean и
сайтом отеля показываем как расхождение, а не выбираем «лучшее» молча. Отсутствие поля не
равно отрицательному свойству. Описания и фотографии не перепубликовываем как свой контент.

## Рекомендуемая цепочка для цен на даты

Бесплатного и правомерного fallback'а к ценам Островка **не найдено**. Порядок такой:

1. Островок, публичные тарифы на даты — как сейчас.
2. Если Островок не дал предложений: показывать публичную цену «от» с 101hotels, явно помечая,
   что это не цена на выбранные даты, и давая ссылку на источник. Дата-зависимый прайс там
   берётся запросом, который закрыт в `robots.txt`, поэтому его не используем.
3. Alean цену без дат в HTML не отдаёт; его тарифы требуют собственного поиска. Для цен не
   применять.
4. TravelLine — только при наличии реквизитов, выданных конкретным отельером, и только в
   сценарии, который ведёт к бронированию: Search API предоставляется под обязательным
   условием использования результатов для создания бронирований.
5. Партнёрские API (Яндекс Путешествия, Bronevik, ETG, Nuitee) остаются выключенными в
   `HOTEL_DATA_MODE=free` и требуют подтверждённых нулевых условий, которых нет.
6. Во всех остальных случаях — честное состояние «цена на эти даты недоступна» с указанием
   проверенных источников. Не подменять цену на даты значением `priceRange`, средней ценой,
   `hotelMinPrice` или ценой частного сектора с Суточно.
