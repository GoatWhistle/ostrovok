# Источник отелей, номеров и доступности

Проверено 2026-10-25 по документации поставщиков. В `.env` есть только ключ Yandex Cloud
для LLM; партнёрских реквизитов гостиничного поставщика нет. У 854 отелей текущего среза
Сочи нет записей о номерах. Живые цены и остатки на стенде сейчас не подтверждены.

## Выбор источника

ETG/RateHawk разделяет статический каталог и проверку тарифов. Его
[Content API](https://docs.emergingtravel.com/docs/content-api/) требует отдельного доступа и
предписывает синхронизировать статические сведения вне пользовательского поиска. В
[ответе каталога](https://docs.emergingtravel.com/docs/content-api/retrieve-hotels-content-by-ids/)
есть адрес, координаты, группы услуг, список платных услуг и категории номеров с удобствами.
Поэтому данные отеля и категорий следует сохранять с отметкой источника и временем обновления.

[Hotelpage API](https://docs.emergingtravel.com/docs/b2b-api/hotel-search/retrieve-hotelpage/)
предназначен для выбранного пользователем отеля и дат: возвращает доступные тарифы, цену,
остаток по тарифу, питание и удобства тарифа. Именно его использует реализованный адаптер.
ETG рекомендует запрашивать его после выбора отеля, а не для каждого отеля выдачи, и
считать тарифы недолговечными. Перед бронированием требуется отдельная
[проверка prebook](https://docs.emergingtravel.com/docs/b2b-api/hotel-search/prebook-rate-from-hotelpage-step/).

Сопоставление OSM ID с ETG `hid` требует проверки имени, адреса и координат; поэтому создана
таблица `hotel_supplier_refs` с уникальными идентификаторами и `verified_at`. Автоматическое
непроверенное сопоставление не включено. До заполнения таблицы тарифный API возвращает
`hotel_unmapped`, а без партнёрских реквизитов — `provider_unavailable`.

Поле `rg_ext.floor` у ETG означает тип этажа (например, мансарда или цоколь),
[а не номер этажа комнаты](https://docs.emergingtravel.com/docs/content-api/retrieve-hotels-content-by-ids/).
Точный этаж и сторону комнаты можно показать только из подтверждённых данных самого отеля.
Значение «всё включено» следует брать из `meal_data.value` конкретного тарифа, а бассейн —
из каталога услуг отеля; наличие бассейна не означает, что он включён в цену проживания.

Для доступа к ETG нужны регистрация, партнёрские реквизиты и, для прямой интеграции,
[проверка интеграции перед production](https://docs.emergingtravel.com/docs/integration-guide/).
Content API предоставляется
[по отдельному запросу](https://docs.emergingtravel.com/docs/content-api/).
После получения доступа: синхронизировать каталог Сочи по расписанию, подтвердить соответствия
OSM и ETG, наполнить карточки локализованными услугами и категориями, проверить живые
предложения на нескольких реальных датах, затем добавить prebook при бронировании.

Booking.com Demand API тоже разделяет
[статические сведения и доступность](https://developers.booking.com/demand/docs/accommodations/about-accommodation),
но [доступ требует управляемого партнёрского аккаунта, токена и affiliate ID](https://developers.booking.com/demand/docs/getting-started/prerequisites).
Покрытие Сочи для имеющегося аккаунта не проверено, поэтому оно не считается подтверждённым.
