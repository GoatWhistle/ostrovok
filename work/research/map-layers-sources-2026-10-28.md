# Открытые источники для новых слоёв карты

Проверено 28 октября 2026 года. Задача — найти слои, которые хорошо выглядят отрисованными рядом
с меткой отеля. Метод: сначала прочитано текущее состояние карты в репозитории (каталог классов,
MVT-слои, импортёр, фронтенд-слои), затем выполнены одиночные запросы к бесплатным публичным API
с паузами в несколько секунд: Overpass API по bbox Сочи и по bbox Красной Поляны, taginfo
Geofabrik по срезу России, GBIF, iNaturalist, STAC earth-search, WMS GEBCO, HTTP Range к
COG-растрам. Ниже у каждого числа указан endpoint, текст запроса и HTTP-статус. Код, конфигурация
и стенд не менялись; регистрации, оплаты и массовые скачивания не выполнялись; ни один файл больше
нескольких десятков килобайт не загружался (растры проверены запросом одного байта через Range).

Что уже установлено прежними заметками и здесь не повторяется:
[ESA WorldCover, ETH Canopy Height, JRC Global Surface Water, GBIF, Black Marble и запрет
Protected Planet](hotel-sources-environment-2026-10-26.md),
[контракты WorldCover/GBIF/OurAirports](nature-tool-contract-2026-10-26.md),
[Overture, GTFS, Open Charge Map, Wikidata](hotel-sources-places-mobility-2026-10-26.md),
[MET Norway, NASA POWER, OpenAQ, Valhalla, Open-Meteo, Meteostat](hotel-sources-weather-routing-2026-10-26.md),
[OSM и Geofabrik как национальный бесплатный срез](free-hotel-data-2026-10-26.md),
[размер и импорт PBF России](russia-map-download.md).

Что уже реализовано в продукте и поэтому не является предложением (проверено по коду):

- Рельеф и подсветка склонов работают из собственного DEM: `raster-dem` и `hillshade` в
  `frontend/src/shared/geo/terrain.ts`, тайлы `/api/v1/map/terrain/{z}/{x}/{y}.png`, кодирование в
  `backend/src/hotel_agent/adapters/geo/terrain_tiles.py`. Источник — `data/seed/sochi/dem.tif`:
  по `data/seed/sochi/meta.json` это Copernicus GLO-30 DSM (`Copernicus_DSM_COG_10_N43_00_E039_00`
  и `..._E040_00`), EPSG:4326, float32, 1620 × 1440, от −3,59 до 1787,91 м, 3 238 812 байт.
- Отдельные деревья **уже есть**: `map_tiles.py` отдаёт MVT-слой `trees` с z ≥ 15, в
  `data/seed/sochi-map/manifest.json` записано `trees: 1732`, `landcover: 17998`,
  `water_areas: 564`, `buildings: 105981`, `roads: 34028`.
- Эти деревья рисуются плоскими кружками: слой `base-trees` типа `circle` в
  `frontend/src/shared/geo/catalog-layers.ts`, радиус от 1,6 до 5,5 px.
- `map-catalog/tree.yaml` и `tree_row.yaml` уже объявляют `props.model` (`tree-pine`, `tree-oak`) и
  `props.scatter_per_1000_m2: 4`, но во фронтенде нет ни одного упоминания `scatter` или `props`:
  модель и плотность не используются.
- `backend/src/hotel_agent/adapters/map_catalog/importer.py` сохраняет только точки
  `natural=tree`, полигоны воды и полигоны landcover. Линии и остальные предметы не сохраняются,
  хотя `bench.yaml`, `fountain.yaml`, `lamp.yaml`, `pier.yaml` в каталоге есть.
- `POI_KEYS` в `backend/src/hotel_agent/adapters/osm/tags.py` включает `amenity`, `leisure`,
  `tourism`, `historic`, `natural`, `man_made`. Значит скамейки, фонтаны, видовые точки,
  водопады, источники, арт-объекты, площадки и пирсы **уже лежат** в таблице `pois`
  (26 519 записей по Сочи) и им не хватает только отрисовки.
- bbox загрузки слоёв — `[39.55, 43.35, 40.0, 43.75]` в `scripts/fetch-map-layers.py`, то есть
  только прибрежный Сочи. Красная Поляна (около 40,05–40,45° в. д.) в него не попадает.

## Что добавлять первым

Оценка визуальной отдачи на единицу работы; это инженерное суждение, а не измеренное влияние на
подбор отелей.

1. **Кроны вместо точек и процедурный разброс деревьев по зелёным полигонам.** Новый источник не
   нужен: 1767 реальных деревьев уже в базе, а зелёных полигонов в bbox намерено 1539
   (`natural=wood` 1077, `leisure=garden` 174, `leisure=park` 159, `landuse=forest` 129). При
   объявленной в каталоге плотности 4 на 1000 м² парк перестаёт быть плоской заливкой и
   превращается в лес. Отдача максимальная, источник нулевой, тени для деревьев в
   `shared/geo/appearance/shadows.ts` уже есть.
2. **Аллеи `natural=tree_row`.** 258 линий в bbox Сочи, 101 168 по России. Это прямой ответ на
   пример «отель стоит в начале аллеи»: цепочка крон вдоль улицы читается на карте мгновенно.
   Геометрия приходит тем же Overpass-ответом, который уже скачивается, но импортёр её выбрасывает.
3. **Предметы из уже загруженных POI.** Ничего не скачивать: 261 водопад, 167 видовых точек,
   116 источников, 116 фонтанов, 843 скамейки, 627 детских площадок, 144 арт-объекта,
   135 исторических объектов в bbox. Водопады и источники — сочинская специфика, которую больше
   никто на карте отеля не показывает.
4. **Подводный рельеф GEBCO 2026.** Единственный по-настоящему новый слой, который меняет вид
   половины каждого скриншота: море сейчас — ровная заливка. Сетка 15 угловых секунд, public
   domain, WMS отвечает 200 по bbox Сочи. Градиент глубины под береговой линией плюс та же
   подсветка склонов, что на суше.
5. **Подъёмники и трассы Красной Поляны.** 129 линий `aerialway` и 414 линий `piste:type` в bbox
   43,60–43,80 / 40,05–40,45. На уже работающем hillshade канатные дороги, уходящие вверх по
   склону, и разноцветные трассы — самая зрелищная новая геометрия. Требует расширить bbox
   загрузки до 40,45° в. д.

Шестым по порядку — точки наблюдений GBIF: 27 089 записей с открытой лицензией в bbox, из них
28 022 по птицам (пересечение неполное из-за разных фильтров). Это уже не украшение, а факт рядом
с отелем, и адаптер `adapters/external/gbif.py` существует.

## OSM: деревья и зелень

Все счётчики получены одним `out count` на `https://overpass-api.de/api/interpreter`,
HTTP 200, `timestamp_osm_base: 2026-10-28T00:33:20Z`, лицензия ODbL. bbox — продуктовый
`(43.35, 39.55, 43.75, 40.0)`.

```text
[out:json][timeout:180];
node["natural"="tree"](43.35,39.55,43.75,40.0);out count;
way["natural"="tree_row"](43.35,39.55,43.75,40.0);out count;
nwr["leisure"="park"](43.35,39.55,43.75,40.0);out count;
nwr["natural"="wood"](43.35,39.55,43.75,40.0);out count;
nwr["landuse"="forest"](43.35,39.55,43.75,40.0);out count;
```

Результат: 1767 деревьев, 258 `tree_row`, 159 парков (3 узла, 122 линии, 34 отношения),
1077 `natural=wood` (2 / 890 / 185), 129 `landuse=forest` (0 / 125 / 4). Отдельным запросом:
`leisure=garden` 174, `landuse=orchard` 649, `natural=beach` 118, `boundary=protected_area` 1,
`route=hiking` 11 отношений, `crop=*` 24.

По всей России числа взяты из собственного экземпляра taginfo Geofabrik,
`https://taginfo.geofabrik.de/russia/api/4/tag/stats?key=natural&value=tree`, HTTP 200,
`data_until: 2026-10-27T21:22:23Z`: `natural=tree` **410 087 узлов**, `natural=tree_row` 101 168.
Это заявленный поставщиком счётчик по срезу России, не мой пересчёт объектов. Для сравнения:
ключ `natural` целиком 6 619 961.

**Важное отрицательное измерение.** Теги, из которых можно было бы сделать факт о дереве, в Сочи
почти не заполнены:

```text
node["natural"="tree"]["species"](...);  -> 11
node["natural"="tree"]["genus"](...);    -> 3
node["natural"="tree"]["height"](...);   -> 5
node["natural"="tree"]["circumference"](...); -> 0
node["natural"="tree"]["denotation"](...);    -> 17
node["natural"="tree"]["leaf_type"](...);     -> 62
```

Значит фразу «отель внутри аллеи двухсотлетних платанов» по OSM **построить нельзя**: ни породы,
ни возраста, ни обхвата ствола в данных нет. Деревья остаются украшением карты и геометрией
аллеи; 17 деревьев с `denotation` (из них часть — `natural_monument`) можно подписать поимённо,
проверив каждое вручную. Возраст не выводится ни из одного доступного открытого источника.

**Как рисуется.** Точка — спрайт кроны с радиусом по зуму и тенью от уже существующего
солнца. Линия `tree_row` — равномерные кроны по длине линии. Полигон — заливка плюс
детерминированный разброс крон (сид от id полигона, чтобы кроны не прыгали между тайлами).
История рядом с отелем: «от подъезда до пляжа 300 м под сплошными кронами», «вдоль дома
проходит аллея длиной 180 м».

## OSM: подъёмники и трассы Красной Поляны

В прибрежном bbox их практически нет: `aerialway` по перечисленным значениям — 4 линии,
`piste:type` — 0. Это следствие границ bbox, а не отсутствия горнолыжного Сочи. Запрос по bbox
Красной Поляны `(43.60, 40.05, 43.80, 40.45)`, HTTP 200:

```text
[out:json][timeout:120];
way["aerialway"](43.60,40.05,43.80,40.45);out count;
way["piste:type"](43.60,40.05,43.80,40.45);out count;
```

Результат: **129 линий `aerialway`**, **414 линий `piste:type`**. По России taginfo даёт
`aerialway` 4243 и `piste:type` 13 543 — то есть почти десятая часть российских трасс
сосредоточена в этом одном прямоугольнике.

Рисуется как линии: канатная дорога — тонкая линия с метками опор и станциями на концах,
трасса — цветная линия по сложности (`piste:difficulty`). Поверх уже работающего hillshade это
читается как схема курорта. История: «от отеля 600 м до нижней станции канатной дороги, трасса
выходит к отелю».

Цена: расширить `BBOX` в `scripts/fetch-map-layers.py` до 40,45° в. д. увеличивает площадь
примерно на 12 % и тянет за собой повторный импорт. Отдельный регион с собственным bbox
аккуратнее, чем расширение сочинского.

## GEBCO 2026: подводный рельеф

Главный довод: на всех текущих экранах море — однотонная заливка, а в Сочи шельф обрывается
близко к берегу. Собственный DEM здесь не помогает: минимум в `meta.json` равен −3,59 м, то есть
глубин в нём нет.

GetCapabilities `https://wms.gebco.net/2026/mapserv?request=getcapabilities&service=wms&version=1.3.0`
вернул HTTP 200, 21 879 байт, слои `GEBCO_2026_Grid` и `GEBCO_2026_SUB_ICE_TOPO`. Реальный
GetMap по сочинскому морю:

```text
https://wms.gebco.net/2026/mapserv?request=getmap&service=wms&version=1.3.0
  &layers=GEBCO_2026_Grid&styles=&crs=EPSG:4326&bbox=43.2,39.3,43.8,40.1
  &width=512&height=384&format=image/png
```

HTTP 200, `Content-Type: image/png`, 22 195 байт, подпись файла `\x89PNG` — картинка настоящая.

Условия: [официальная страница сеток](https://www.gebco.net/data-products/gridded-bathymetry-data)
говорит «The GEBCO Grid is placed in the public domain and may be used free of charge» и просит
указывать источник со ссылкой на DOI сетки GEBCO_2026. Разрешение — интервал 15 угловых секунд,
то есть около 460 м по широте: это плавный градиент, а не донный рельеф у пирса.
`AccessConstraints` в GetCapabilities прямо запрещает использование для навигации и задач
безопасности на море — на карте отеля это и не требуется, но предупреждение надо сохранить в
подписи. Коммерческое использование на странице отдельно не оговорено; формулировка «public
domain» его не исключает.

Как рисуется: растровый слой под береговой линией, окрашенный по глубине, либо собственные
изолинии глубин. История: «в 900 м от берега дно уходит на сто метров», «отель на участке, где
шельф самый широкий». Числа глубины публиковать только как значение сетки с указанием шага 15″.

## GBIF: наблюдения как слой точек

`https://api.gbif.org/v1/occurrence/search`, анонимно, HTTP 200 на каждый запрос.

| Запрос | Результат |
|---|---|
| `decimalLatitude=43.35,43.75&decimalLongitude=39.55,40.0&hasCoordinate=true&hasGeospatialIssue=false&limit=0` | `count: 67440` |
| то же + `license=CC0_1_0&license=CC_BY_4_0` | `count: 27089` |
| то же + `basisOfRecord=HUMAN_OBSERVATION&year=2015,2026` | `count: 15933` |
| `taxonKey=212` (Aves), bbox Сочи | `count: 28022` |
| `taxonKey=5314` (Delphinidae), bbox 43,0–44,0 / 39,0–40,5 | `count: 127` |
| `datasetKey=50c9509d-...` (iNaturalist Research-grade), bbox Сочи | `count: 39376` |

Фасет по наборам на подмножестве с открытой лицензией (`facet=datasetKey&facetLimit=5`):
eBird Observation Dataset 7481 (CC BY 4.0), iNaturalist Research-grade 6027, Moscow University
Herbarium 3338 (CC BY 4.0), «Phytoplankton samples collected near Sochi, Black Sea, in 1974-1975»
2034 (CC BY 4.0), ещё один набор 1336. Названия и лицензии получены из
`https://api.gbif.org/v1/dataset/<key>`.

Существенная подробность о лицензиях: набор iNaturalist на уровне набора объявлен
`creativecommons.org/licenses/by-nc/4.0`, то есть некоммерческим, но 6027 его записей в этом же
bbox отдают в поле `license` CC0 или CC BY. Значит отбирать надо **по полю записи**, а не по
лицензии набора; иначе либо потеряем шесть тысяч пригодных точек, либо возьмём тридцать девять
тысяч непригодных. Остальные правила обращения с GBIF уже зафиксированы в
[контракте инструментов природы](nature-tool-contract-2026-10-26.md) и здесь не дублируются.

Как рисуется: точки с радиусом по неопределённости координат либо тепловая карта по видам, и
отдельная «птичья» подложка. История: «в радиусе 500 м от отеля опубликованы наблюдения
28 тысяч записей о птицах с 2015 года». Дельфины как слой слабые: 127 записей на прямоугольник
в полтора градуса — это редкие точки, а не линия миграции.

## iNaturalist: больше точек, но лицензия не подтверждена

`https://api.inaturalist.org/v1/observations`, без ключа, HTTP 200 на каждый запрос,
bbox задан как `nelat=43.75&nelng=40.0&swlat=43.35&swlng=39.55`.

| Запрос | Результат |
|---|---|
| `per_page=0` | `total_results: 79636` |
| `quality_grade=research&license=cc0,cc-by&per_page=0` | `total_results: 6102` |
| `/v1/observations/species_counts?...&per_page=0` | `total_results: 4422` |
| `taxon_name=Cetacea&per_page=0` | `total_results: 0` |

79 636 наблюдений против 67 440 у GBIF: iNaturalist по Сочи плотнее, и у наблюдений есть фото.
Но подтвердить условия использования сегодня не удалось:
`https://www.inaturalist.org/pages/api+recommended+practices` вернул HTTP 403 и страницу-заглушку
Cloudflare и через web-инструмент, и через curl. Поэтому документированные лимиты частоты,
требование User-Agent и допустимость коммерческого использования остаются **непроверенными**.
Нулевой ответ по `taxon_name=Cetacea` тоже считать непроверенным: это может быть особенность
формы запроса, а не отсутствие китообразных.

Практический вывод: пока лицензия не прочитана, те же наблюдения iNaturalist брать через GBIF, где
лицензия каждой записи возвращается в ответе и уже разобрана. Это теряет часть свежих записей, но
не создаёт правового риска.

## Растровая зелень и высота кроны

Новое измерение к уже описанным наборам: сам COG высоты кроны **доступен**. Range-запрос одного
байта к
`https://libdrive.ethz.ch/index.php/s/cO8or7iOe5dT2Rt/download?path=%2F3deg_cogs&files=ETH_GlobalCanopyHeight_10m_2020_N42E039_Map.tif`
вернул HTTP 206, `Content-Range: bytes 0-0/221189590`, `Content-Type: image/tiff`. То есть
211 МБ файл читается частями без скачивания целиком, лицензия CC BY 4.0. Прежняя заметка оставляла
доступ к растру непроверенным.

Для карты это не слой, а параметр: высота кроны из модели 2020 года задаёт высоту разбрасываемых
крон внутри полигона леса, и лес перестаёт быть одноростным. Ограничение прежнее: это модель, а не
измерение конкретного дерева, и показывать её надо с годом и неопределённостью. ESA WorldCover
в этой роли даёт более грубое, но готовое разделение «лес / кустарник / трава / застройка» для
окраски зелёных зон; адаптер `adapters/geo/worldcover.py` в репозитории уже есть.

## Спутниковая подложка

**Sentinel-2 L2A через STAC — работает и годится.** POST на
`https://earth-search.aws.element84.com/v1/search` с телом

```json
{"collections":["sentinel-2-l2a"],"bbox":[39.55,43.35,40.0,43.75],
 "datetime":"2026-06-01T00:00:00Z/2026-09-30T23:59:59Z",
 "query":{"eo:cloud_cover":{"lt":5}},"limit":1}
```

вернул HTTP 200 и `numberMatched: 23`. Лучшая сцена — `S2A_37TEJ_20260913_1_L2A` от 13 сентября
2026 с облачностью 0,046 %. Её готовый цветной композит
`https://sentinel-cogs.s3.us-west-2.amazonaws.com/sentinel-s2-l2a-cogs/37/T/EJ/2026/9/S2A_37TEJ_20260913_1_L2A/TCI.tif`
на Range-запрос ответил HTTP 206, `Content-Range: bytes 0-0/245512688`,
`Content-Type: image/tiff; application=geotiff; profile=cloud-optimized`. То есть 234 МБ читаются
частями, анонимно, без AWS-аккаунта.
[Реестр AWS](https://registry.opendata.aws/sentinel-2-l2a-cogs/) подтверждает бесплатный и
открытый доступ, бакет `sentinel-cogs` в `us-west-2`, работу с `--no-sign-request` и отсутствие
требования аккаунта.

Это единственный найденный путь к спутниковой подложке, который не упирается в некоммерческую
лицензию. Цена — наша: нарезать и кешировать тайлы придётся самим, 23 сцены за сезон нужно
отобрать и склеить.

**EOX Sentinel-2 cloudless — отвергнуто.** Тайл
`https://tiles.maps.eox.at/wmts/1.0.0/s2cloudless-2020_3857/default/g/11/747/1252.jpg` отвечает
HTTP 200, 8543 байта, то есть сервис работает и подключается в одну строку. Но
[страница лицензии](https://cloudless.eox.at/documentation/license) разрешает бесплатное
использование только в некоммерческих целях по CC BY-NC-SA 4.0, а для коммерческого требует
отдельную лицензию EOX Commercial Attribution-RestrictedUse 1.2. Требуемая атрибуция:
«EOxCloudless https://cloudless.eox.at by EOX IT Services GmbH (Contains modified Copernicus
Sentinel data "year")». Для продукта, который может стать коммерческим, не брать.

**OpenAerialMap — пусто по Сочи.** `https://api.openaerialmap.org/meta?bbox=39.55,43.35,40.0,43.75&limit=3`
вернул HTTP 200 и `{"license":"CC-BY 4.0", ..., "found":0, "results":[]}`. Лицензия подходящая,
снимков по нашему городу нет.

**Панорамы.** Mapillary требует бесплатной регистрации и токена; регистрация не выполнялась, поэтому
покрытие Сочи не измерено. Фотографии Wikimedia Commons уже подключены адаптером
`adapters/external/commons_photos.py`, отдельного исследования не требуют.

## Рельеф вне среза Сочи

Собственный DEM покрывает только продуктовый bbox, а в продукте есть общероссийские слои. Готовая
бесплатная замена для мелких масштабов — архив AWS terrain-tiles. Проверено Range- и
HEAD-запросами, все HTTP 200:

| Тайл | Размер | `x-amz-meta-x-imagery-sources` |
|---|---|---|
| `terrarium/11/1252/747.png` (Красная Поляна) | 65 251 | `eudem_dem_5deg_n40e040.tif`, `srtm/N43E040.tif` |
| `terrarium/11/1250/748.png` (прибрежный Сочи) | 31 129 | `eudem n40e035`, `srtm/N43E039`, `gmted` |
| `terrarium/12/2505/1494.png` | 50 527 | `eudem n40e040`, `srtm/N43E040` |
| `normal/12/2505/1494.png` | 107 412 | то же |

Формат `terrarium` читается MapLibre как `raster-dem` напрямую, формат `normal` — готовые нормали.
`Last-Modified` у одного из тайлов — 17 ноября 2017 года: это статический архив, а не обновляемый
сервис. Атрибуция обязательна и собирается по провайдерам,
[официальный список формулировок](https://raw.githubusercontent.com/tilezen/joerd/master/docs/attribution.md)
для европейской части требует строку «Europe terrain data produced using Copernicus data and
information funded by the European Union - EU-DEM layers» и упоминание USGS для SRTM и GMTED2010.

Вывод: для Сочи наш GLO-30 точнее и уже работает, менять не на что. Архив полезен ровно для одного
случая — рельеф на общероссийском зуме, где собственного DEM нет.

## Высоты зданий: почему объём придётся считать по этажам

Измерено по Overpass, bbox Сочи, HTTP 200:

```text
way["building"](...)                      -> 105 830
way["building"]["building:levels"](...)   ->  37 211
way["building"]["height"](...)            ->     107
```

То есть `building:levels` есть у 35,2 % контуров, а метрическая `height` — у 0,10 %. По России
taginfo даёт `building:levels` 3 242 333 и `height` 334 715. Значит экструзия должна и дальше
строиться от этажности с явной отметкой источника высоты, а `height_source` в таблице `buildings`
остаётся обязательным полем. Overture Buildings как источник высот уже
[разобран прежней заметкой](hotel-sources-places-mobility-2026-10-26.md) и ничего не обещает по России.

## Тупики и то, что проверить не удалось

- **Городские реестры деревьев России.** DNS разрешается (`data.mos.ru` 212.11.155.167,
  `opendata.krasnodar.ru` 46.226.227.228, `data.gov.ru` 82.202.191.80; `admsochi.ru` не
  разрешается вообще). Но curl в этой среде на все три вернул `HTTP 000` с ошибкой 60 «SSL
  certificate problem: unable to get local issuer certificate», при том что `openssl s_client`
  к `data.mos.ru` проверяет цепочку успешно (`issuer=C=BE, O=GlobalSign nv-sa, CN=GlobalSign GCC
  R6 AlphaSSL CA 2025`, `Verify return code: 0 (ok)`). Это дефект хранилища корневых сертификатов
  в среде проверки, а не недоступность портала; тот же класс проблемы прежняя заметка
  зафиксировала для Python HTTPS. Через web-инструмент `data.mos.ru` открывается, но это SPA, и
  список наборов из разметки не извлекается. Программный доступ
  `https://apidata.mos.ru/v1/datasets?$top=1` вернул HTTP 401. Ключ выдаётся по бесплатной
  регистрации; регистрация не выполнялась по условиям задачи. Набора о деревьях Сочи или
  Краснодарского края найти не удалось. Итог: **непроверено, не тупик окончательно** — сначала
  починить доверенные сертификаты, затем запросить бесплатный ключ data.mos.ru и посмотреть,
  существует ли аналог для Краснодарского края.
- **Возраст и порода дерева.** Ни одного открытого источника не найдено. В OSM по Сочи
  `species` у 11 деревьев из 1767. Истории про «двухсотлетний платан» писать нельзя.
- **Горнолыжные трассы в прибрежном bbox.** `piste:type` — ровно 0. Без расширения bbox слой пуст.
- **Protected Planet.** Остаётся запрещённым для коммерческого использования, как установлено
  [прежней заметкой](hotel-sources-environment-2026-10-26.md). Для охраняемых территорий остаётся
  OSM: в bbox всего 1 объект `boundary=protected_area`, то есть слой по Сочи почти бесполезен.
- **EOX s2cloudless.** Технически идеален, лицензия CC BY-NC-SA 4.0 закрывает дорогу.
- **OpenAerialMap.** `found: 0` по Сочи.
- **OpenAQ v3.** `https://api.openaq.org/v3/locations?coordinates=43.58,39.72&radius=25000&limit=1`
  вернул HTTP 401 и тело `{"message": "Unauthorized. A valid API key must be provided in the
  X-API-Key header."}`. Ключ бесплатный, но требует регистрации, которая не выполнялась. Число
  станций рядом с Сочи остаётся неизмеренным.
- **Условия iNaturalist.** HTTP 403 (Cloudflare) на страницу правил. Сам API отвечает 200.
- **Пешеходные маршруты как слой.** 11 отношений `route=hiking` в bbox — слишком мало для
  отдельного слоя; тропы и так есть в `roads` как `road_path`.
- **Световое загрязнение и шумовые карты.** Уже разобраны прежними заметками: VIIRS EOG с июня
  2026 платный для программного доступа, NASA Black Marble требует бесплатный Earthdata-токен,
  европейская карта шума Россию не покрывает. Новых бесплатных вариантов не найдено, и в продукте
  уже есть собственные `noise_sources` (2015 объектов) и ночная подсветка города.
