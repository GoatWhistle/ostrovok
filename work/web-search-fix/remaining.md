Работа остановлена по просьбе пользователя 26 октября 2026 года. Ветка — `feat/hotel-agent-mvp`; HEAD перед сохранением — `2d2fd12`. Тестовый контейнер `hotel-research-evaluation` остановлен, временные файлы с окружением удалены. Новые обращения к модели не запускаются.

## Что сделано

- Добавлен поиск ID отеля по названиям, сохранённым вариантам названия и адресу. Он не требует предварительного подтверждения пожелания.
- `search_documents` отдельно возвращает кандидатов для сопоставления идентичности отеля.
- Бюджет текста проверяющего: до 40 000 символов одной записи, до 48 000 на пакет. Сохранена проверка дословной цитаты.
- В проверку страницы передаются метаданные идентичности отеля из каталога.
- Проверенное совпадение сохраняется сразу после чтения страницы.
- Для уже проверенного текстового поля склонение пожелания больше не блокирует создание факта. Числовые непроверенные критерии это исключение не получают.
- Прочитанные страницы переиспользуются между пожеланиями одного запроса; каждое пожелание проходит отдельную проверку.
- Ранее реализованные исправления афиши входят в эту же задачу: поиск без дат проживания, прямой публичный поиск Яндекс Афиши, сопоставление площадки и проверка расстояния.
- В промпте нет специальных правил для конкретного человека или отеля.

## Продолжить в таком порядке

1. **Довести проверку источника до устойчивого результата.** Исследовать расхождение между промежуточной проверкой цитаты и итоговой проверкой рекомендации. Возвращать отказ проверяющего в исследовательский цикл, чтобы агент искал другое подтверждение, вместо завершения с пустой выдачей. Не ослаблять проверку ради появления карточки.
2. **Устранить повторное исследование одного условия.** Парсер иногда выдаёт одновременно короткое пожелание и весь запрос с тем же пожеланием. Кэш страниц сокращает повторение, но не убирает дубликат из списка условий. Сохранить действительно разные или более строгие условия; не удалять их простым поиском подстроки.
3. **Уточнить обработку недоступных страниц.** В трассах есть повторные обращения к одной странице с URL в разных кодировках, блокировки и страницы без содержимого. Различать причины отказа, канонизировать повторы и направлять поиск к другим источникам. Не подменять полный источник поисковым сниппетом.
4. **Проверить положительные результаты вручную.** В частности, источник для «Националя» должен подтверждать проживание, конкретное место и время. Не подгонять проверку под заранее выбранный отель. Проверить, что историческое название сопоставлено с правильным нынешним объектом.
5. **Закончить 12 случаев из cases.json.** После следующих исправлений повторить исходный запрос и Есенина, затем завершить остальные десять. Для каждого записать время, итоговые отели, цитаты, ссылки и вердикт по заранее заданному критерию. Невозможное условие и современная имитация старинного замка не должны получать ложного подтверждения. Дополнительно повторить несколько успешных случаев для проверки устойчивости.
6. **Собрать и развернуть окончательную версию.** Первая часть исправлений была развёрнута как `research-fix-20261026`; затем параллельная сессия сменила основной образ на `view-corridor-20261026`. Последние изменения склонений и повторного использования страниц отдельно на основном стенде не подтверждены. Сначала сравнить содержимое актуального образа с исходниками. Сохранить текущие настройки модели и изменения соседней задачи, затем выполнить HTTP-проверку после развёртывания.
7. **Обновить доказательства и ограничения.** Сохранить отрицательные результаты рядом с положительными. Не объявлять все запросы исправленными по одному успешному прогону. Проверить бюджет context и актуальные ветку/SHA.

Следующий запуск живой модели и развёртывание — только после возобновления этой задачи пользователем. Остановка не означает завершения всех исправлений.
