# E03 — здания в обзорных MVT

Дата: 2026-10-27. Изолированный PostGIS E00, исходный срез Сочи и существующий подготовленный `sochi-map/layers.geojson.gz`. Импорт карты добавил 17 998 объектов landcover, 564 water_areas и 1 732 дерева; классифицировал 105 981 здание. Основной стенд и российский импорт не затронуты.

До изменения центральный тайл z12 содержал 0 зданий при 8 562 контурах в БД; z14 — 0 при 882. `e03-before.json` содержит 21 декодированный тайл трёх камер. После исправления z10–11 содержит крупные здания и фактические полигоны жилых/коммерческих/промышленных районов; z12–13 — отдельные контуры с упрощением 1 м; z14+ — исходные контуры. Обзорное землепользование упрощено до 5 м. Субпиксельные полигоны может отбросить кодировщик; это не отсутствие исходных зданий.

Каждый building сохраняет строковый id, класс и происхождение класса/высоты. Буфер 64/4096 согласован с пространственным отбором. Область без данных возвращает пустой тайл. /map/scene остаётся локальным.

Первые замеры дали 447 мс на плотном береговом тайле. EXPLAIN показал затраты преобразования/упрощения, поэтому две миграции добавляют сохранённые вычисляемые проекции buildings/landcover/water. Они пересчитываются при изменении исходной геометрии; отдельной ручной пересборки не требуется. Миграции применены на тестовой базе и многократно на свежих disposable-базах тестов. На рабочей базе их ещё предстоит применить при итоговом запуске.

Версия `buildings-v2` включена в URL клиента и /map/style. Неверная версия даёт 409; неверсионированный и пустой ответ не кэшируются; заголовок X-Map-Tile-Version содержит текущую версию. Реальный HTTP: 200, 515 443 байта для 12/2499/1495, cache max-age=86400. Генератор frontend теперь по умолчанию читает канонический docs/api/openapi.yaml; API_SCHEMA_URL остаётся переопределяемым. До исправления он пытался обратиться к отсутствующему localhost:8000; runtime-schema использует другие имена компонентов, поэтому её нельзя незаметно подставлять вместо канонического контракта.

Проверки:
- Ruff и mypy: успешно, 485 Python-файлов.
- Unit + contract + integration: 904 passed, 20 предупреждений существующих зависимостей. Отдельные 11 проверок декодированных MVT проверяют 10–17, свойства, валидность геометрии, обе стороны границы, изменение исходного контура и пустой участок.
- Frontend verify: 36 правил, типы, lint, 416 тестов и сборка.
- 24 разных тайла, пять прогретых запросов каждый: n=120, p95=125,574 мс, максимум=217,41 мс. Метод и исходные значения в `e03-measured.json`, повторяемый скрипт `measure_tiles.py`; первый запрос измерен отдельно. Это SQL+кодирование локального стенда, без клиентского рендера и сети. Пустые горные тайлы включены и явно отмечены, значения плотного берега доступны отдельно.
- Запуск измерения: из корня, `DATABASE_URL=<тестовая БД> TILE_EVIDENCE=<отчёт.json> backend/.venv/bin/python work/frontend-evolution/evidence/measure_tiles.py`.

Использованы семантика [ST_AsMVT](https://postgis.net/docs/ST_AsMVT.html) и [ST_SimplifyPreserveTopology](https://www.postgis.net/docs/ST_SimplifyPreserveTopology.html). Декодирование тестов выполняет dev-зависимость [mapbox-vector-tile](https://github.com/tilezen/mapbox-vector-tile); в runtime она не входит.

Клиентские minzoom, визуальная проверка и лёгкие объёмы остаются E04. Обзорная застройка показывает только импортированное покрытие, не искусственные дома на всей территории России.
