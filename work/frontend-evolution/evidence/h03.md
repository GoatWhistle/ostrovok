# H03: формы ответа по типам и общие значения

2026-10-27, `feat/hotel-agent-mvp`, исходный HEAD `5d4fe0f`. Стенд: Vite :5179 → изолированный
API :18085 (FakeLLM, PostGIS :15435). Платные модели не вызывались.

## Что сделано

- Контракт: `Characteristic.answer_fields` (`name`, `kind` bool|number, `unit`) из полей реестра,
  до изменения кода; типы фронтенда сгенерированы. Числа внутри объектного исправления
  отклоняются, если отрицательные, как и обычные числовые факты.
- `entities/catalog/answer-fields`: модель черновика (числа с точкой или запятой, пустое ≠ 0,
  «не знаю» ≠ false, скрытые условия не входят в ответ), сборка читаемого текста, типизированное
  значение для `/correct`, чтение старых текстовых черновиков как пояснения.
- Форма вопроса: поля по реестру, предпросмотр «Будет отправлено», одна кнопка сохранения.
  Быстрый выбор больше ничего не отправляет. «Не знаю» стал вариантом значения,
  переход к следующему вопросу назван «Следующий вопрос». При некорректном числе кнопка
  остаётся активной: отправка показывает ошибку у поля и переводит на него фокус, без запроса.
- Исправление факта: те же поля. У питомцев появилось редактирование, булевы значения
  подписаны свойством («Есть/Нет», «Можно/Нельзя») вместо подписей совпадений поиска,
  пояснение уходит комментарием. Текстовые факты остаются полем ввода.
- «Сейчас в выдаче» выбирает факт по статусу и свежести, а не по максимальной уверенности.

## Ограничения и остатки

- Остальные 4 сценария `e2e/hotel-workspace.spec.ts` падают одинаково и на `5d4fe0f`
  (проверено отдельным worktree на :5180). Они не учитывают навигацию E01–E10; передано в E16.
- Собранный текст в EN-интерфейсе английский: автономный FakeLLM разбирает только русские фразы
  реестра, поэтому в английском интерфейсе он вернёт уточнение. Настоящая модель понимает оба.
- Мобильный порядок «очередь, потом форма» и ссылка пропуска поверх заголовка видны на снимке 375 px:
  это задачи H05 и E14, здесь не менялись.
