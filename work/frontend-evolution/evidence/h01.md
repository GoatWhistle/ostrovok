# H01: черновики, проверка чисел и защита отправки

Проверено 2026-10-27 поверх baseline `63bef5f`; baseline-коммит `9fca676`.
Исправления закрывают P0 замечания 01–03 аудита.

- Черновик хранится в sessionStorage по hotel/question ID или immutable fact ID.
  При ошибке хранилища остаётся в памяти, показывается предупреждение и включается beforeunload.
  Более новый ввод не удаляется поздним успехом. Follow-up не очищает ответ без извлечённого факта.
- Состояние мутации живёт в QueryClient по ID, доступно после смены вопроса/повторного mount.
  Общий guard отклоняет повторный вызов, пока идёт запись; confirm/correct используют один ключ.
  Повторный mount не теряет pending, ошибку или результат текущего запроса.
- Пустота, пробелы, текст, смешанные разделители, бесконечность и отрицательные числа
  отклоняются до POST. Граница >=0 совпадает с ChangeFacts на сервере; запятая и точка допустимы.
  Ошибка связана с полем через aria-describedby и aria-invalid, объявляется role=alert.
- Пока запись выполняется, вся группа действий и поля заблокированы. Другой вопрос открыть можно.
