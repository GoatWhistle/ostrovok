# H02: отложенные вопросы и сохранённый ответ в API

2026-10-27, `feat/hotel-agent-mvp`, исходный HEAD `6b79d11`. Изолированный стенд
`hotel-evolution`: API :18085 (FakeLLM, исходники смонтированы, контейнер перезапущен),
PostGIS :15435. Платные модели не вызывались.

## Что сделано

- Контракт изменён до кода: `PATCH /hotelier/questions/{question_id}` с телом
  `{"status": "open" | "skipped"}` (лишние поля запрещены), ответ — актуальный `HotelierQuestion`;
  404 для неизвестного ID, 409 `question_answered` для отвеченного, 422 для неверного тела.
  В `HotelierQuestion` добавлены необязательные `answer_text`, `answered_at`, `answer_fact_ids`.
  Операций стало 27, проверка контракта обновлена.
- Домен: `skipped()` и новый `reopened()` идемпотентны; отвеченный вопрос отклоняется ошибкой
  `QuestionAnswered`. `answered()` и существующий ответ не изменены.
- `ChangeQuestionStatus` читает вопрос под `FOR UPDATE`, пишет только при реальной смене статуса,
  не трогает факты и не вызывает модель.
- Новая таблица и миграция не понадобились: `answer_text` и `answered_at` уже хранились.
  `answer_fact_ids` читается подзапросом из `facts` по `source_type = 'hotelier'` и
  `source_id = id вопроса` в порядке создания. Старые записи без связи дают пустой список.
- Типы фронтенда сгенерированы из контракта (`npm run api:types`). Потребители в UI появятся в H04.

## Проверки

- Ruff и mypy по всему backend (492 файла). Посторонний `adapters/external/ostrovok_details.py`
  не проходит `ruff format --check` ещё до этой задачи; не трогался.
- Unit + contract: 875 тестов. Новые: обратимое и повторяемое отложение, запрет для отвеченного,
  отложенный вопрос не принимает ответ до возврата, сохранённые текст/время/факты в списке,
  неизменность состояния и отсутствие коммита при отказе; PATCH 200/404/409/422 и схемы контракта.
- Integration на настоящей PostGIS (`tests/integration/repository`, 41 тест):
  отложение переживает новое соединение; после возврата ответ сохраняется и связывается с фактом;
  запись без связи даёт пустой список; **отложение во время вызова модели** (модель ждёт сигнала)
  выполняется сразу, без ожидания блокировки, а поздний ответ отклоняется без факта;
  одновременные ответ и отложение дают ровно один согласованный исход.
- HTTP на стенде (`check-h02-api.py` → [h02-api.json](h02-api.json)): skip 200 и список показывает
  skipped, повтор 200, reopen 200 и open, skip/reopen отвеченного 409, неизвестный 404, `answered`
  и лишнее поле 422. Отвеченные демо-вопросы отдают свои тексты, время и ID фактов из provenance.
  Последний открытый демо-вопрос `q_h_demo_hotelier_room_capacity` оставлен открытым для ручной
  проверки; ответ через HTTP не отправлялся, путь ответа покрыт интеграционными тестами с FakeLLM.
- Frontend `npm run verify`: 36 правил, 488 тестов в 90 файлах, сборка.

`tests/integration/e2e` не запускался: он требует полностью засеянного основного стенда и
не относится к изменённому пути.
