# План реализации по проверяемым этапам

Статус: выполняется по разрешению пользователя в `feat/hotel-agent-mvp`. Требования: [spec.md](spec.md),
решения: [architecture.md](architecture.md), кабинет: [hotelier.md](hotelier.md), проверки: [acceptance.md](acceptance.md).
Пути к коду относятся к актуальному checkout `../o-hack-sochi`; новые имена модулей — предложения.

## Порядок работы и границы этапов

Рекомендуемая последовательность: **E00 → H01 → E01–E08 → E18 → E12 → E10 → E09 → E11 →
H02–H07 → E13–E17**. E12 намеренно раньше новых страниц: читаемость карточек не зависит от полной навигации.
Контрактные проверки E13 выполняются и внутри затронутых этапов, а в конце сводятся в общий отчёт.
После каждого завершённого и проверенного пункта — отдельный локальный коммит с результатом и
доказательством проверки. Самостоятельные подпункты с отдельным результатом также коммитить отдельно;
не объединять несколько уже готовых пунктов в один финальный коммит. Проверочные пункты без изменения
кода фиксируются коммитом отчёта. Названия коммитов у этапов ниже — ориентиры для соответствующего изменения.
**Промежуточные push запрещены: один итоговый push только после всех E00–E18/H01–H07 и их проверок.**
Разрешение на реализацию получено 2026-10-27; прежнее ограничение «только спецификация» снято.

Статусы: `planned`, `in_progress`, `blocked` с конкретной причиной, `verified` со ссылкой на доказательство.
Актуальные статусы и доказательства находятся в [progress.md](progress.md). Невыполненный обязательный критерий нельзя закрыть снимком другого сценария.
Работа последовательная; параллельные агенты этим планом не запускаются.
