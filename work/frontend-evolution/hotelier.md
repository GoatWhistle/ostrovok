## 2. Рабочая область показывает один текущий вопрос

```text
Название отеля                         Сменить отель
Нужно уточнить: N                      Как видят гости

Нужно уточнить | Отложено | Готово

Темы вопросов                Тема текущего вопроса
Короткое название             Текущее значение и существенные ограничения
Короткое название             Полный вопрос
                             Форма по типу характеристики
                             Пояснение и условия
                             Сохранить ответ       Отложить
                             Источник и история
```

`N` вычисляется из ответа API, без фиксированного числа из демо. На широкой рабочей области
не растягивать текст формы на всю ширину 2560 px: читаемая колонка и соседний контекст вопроса.
Сохранить Manrope, существующие navy/cyan поверхности и светлые токены. Один основной CTA.

На мобильном первым показывается текущий вопрос. «Все вопросы» открывает отдельное состояние
очереди, выбор возвращает к форме с заголовком в видимой области. Возврат сохраняет прокрутку очереди.
Даты/гости существуют только в туристическом предпросмотре; на узкой ширине поля дат в одну колонку.

«Как видят гости» открывает самостоятельный предпросмотр из общих туристических блоков R5.
Он закрывается той же кнопкой, крестиком и Escape; фокус возвращается к триггеру. Нельзя монтировать
внутри него ещё одно полное приложение с дополнительными постоянно работающими картами.

## 3. Черновик не зависит от монтирования формы

Ключ черновика: версия схемы + `hotelId` + `questionId`; для исправления факта — `factId` и его версия.
Состояние хранится выше переключаемой формы и сохраняется в sessionStorage той же вкладки.
Это проектное решение: восстановление после reload и ухода к другому отелю обязательно,
синхронизация между устройствами не обещается. Хранить только несохранённый ввод, без ключей провайдера.

- В памяти: выбранные значения, пояснение, dirty, ошибки полей, свёрнутость редактора.
- Отдельно по вопросу/факту: pending, ошибка запроса, подтверждённый результат и request ID.
- Успех очищает только отправленную версию черновика; текст, введённый позже, не удаляется.
- Ошибка не очищает ввод и остаётся доступной после смены вопроса. В очереди есть индикатор ошибки.
- Reload не восстанавливает `pending` как бесконечную загрузку. Сначала перечитать сервер;
  при неоднозначном результате не отправлять POST автоматически повторно.
- При недоступном storage ввод остаётся в памяти; показать, что reload его потеряет, и дать
  сохранить/отменить уход при dirty. Это состояние проверяется, а не подавляется try/catch без UI.
- При смене отеля старый ответ не отображается у нового; поздний результат обновляет только свой ключ.
- После подтверждённой отмены сбросить черновик к актуальному сохранённому значению и убрать локальную ошибку.

На время мутации блокируется вся группа действий над той же сущностью, включая клавиатурный submit.
Подтвердить/correct используют общий lock по fact ID; answer/skip — общий lock по question ID.
Навигация к другому вопросу допустима, поскольку состояние исходного запроса сохраняется отдельно.
UI-lock не заменяет транзакционную защиту сервера; гонки двух клиентов проверяются интеграционно.

## 4. Форма сохраняет значение вместе с условиями

| Тип | Поля | Валидация и сохранение |
|---|---|---|
| Boolean | Предметные «Есть/Нет» либо «Разрешено/Не разрешено» и неизвестное состояние | Выбор меняет ввод, одна кнопка отправляет весь ответ |
| Number | Число, единица из реестра, пояснение | Trim до преобразования; конечное число; диапазон только из доменных правил |
| Object: pets_policy | allowed, подтверждённые поля веса/доплаты, пояснение | Неизвестное не false; пустое не 0; не добавлять вид питомца/период оплаты по догадке |
| Текстовый/неподдержанный структурированный тип | Понятное текстовое поле и пояснение | Без сырых JSON-редакторов; существующий API извлечения и явный follow_up |

Для числа принять десятичную точку и локальную запятую по однозначному правилу; смешанный или
неоднозначный формат отклонить с подсказкой. `0` и `false` допустимы, если реестр не задаёт запрет.
Ошибка выводится у поля, связана через `aria-describedby`, поле получает `aria-invalid`.

Существующий answer endpoint принимает `text`, поэтому типизированная форма строит из введённых
полей полный проверяемый текст, который пользователь может прочитать до отправки. В него не добавляются
невведённые условия. Извлечённый сервером результат остаётся источником истины; форма не выдаёт
отправленный текст за уже сохранённый факт. Correct отправляет типизированный `value` по контракту.

Условия питомцев форматируются общим модулем: разрешение, известный вес, известная доплата.
`fee_rub` позволяет назвать рубли, но не «в сутки», если период не подтверждён данными/исходным ответом.
Фотографии, цены и звёзды туристического предпросмотра следуют правилам R5.

## 5. Сохранение имеет явные исходы

| Ответ сервера | Что остаётся в центре | Следующее действие |
|---|---|---|
| Созданы факты, без конфликта | «Ответ сохранён», полученное значение, время из данных | «Следующий вопрос», «Изменить» |
| `follow_up` | Уточнение рядом с предыдущим ответом | Дополнить ответ, сохранить заново |
| Есть conflict | Значения и объяснение противоречия | Предусмотренное исправление/подтверждение; не зелёный безусловный успех |
| Ошибка | Черновик и объяснение ошибки | Повтор с тем же вводом после проверки состояния |
| Все отвечены | Понятный итог, раздел «Готово» | Просмотр и исправление сохранённых сведений |
| Нет вопросов | Честное пустое состояние | Смена отеля или просмотр сведений; без выдуманной задачи |

Автовыбор первого вопроса записывается как явный выбранный ID. Нельзя связывать показ успеха с тем,
нажимал ли пользователь строку очереди. Автоматически исчезающий toast не заменяет сохранённый итог.
Историческая причина `missing` у отвеченного вопроса относится к истории; текущий экран не говорит
«Не хватает данных» рядом с окончательным «Готово», если нового недостатка нет.

У отвеченного вопроса изменение идёт через актуальный связанный факт и `/correct`, а не повторный
`/answer` для answered: сейчас сервер принимает answer только для open. Если связь не восстановлена,
показать сохранённый ответ и честное ограничение, не исправлять случайный факт той же характеристики.

## 6. Для отложения и сохранённого ответа нужен конкретный контракт

Это запланированное расширение, его **нет** в текущих 26 операциях. Реализуется в H02 до UI отложения.

**Предлагаемая операция:** `PATCH /api/v1/hotelier/questions/{question_id}`,
тело `{ "status": "skipped" }` или `{ "status": "open" }`, ответ 200 — актуальный `HotelierQuestion`.
Допустимы open → skipped, skipped → open и повтор уже достигнутого статуса. Answered нельзя вернуть
в open этой операцией: 409 с актуальным состоянием. Неизвестный ID — 404, неверное тело — 422.
Переход транзакционный, под блокировкой строки; он не изменяет факт и не вызывает LLM.

- После успешного отложения вопрос виден в «Отложено» и сохраняет статус после reload.
- «Вернуть в работу» делает PATCH open; затем действует существующий answer endpoint.
- Если answer уже завершился в другом клиенте, skip не перезаписывает answered.
- Если skip завершился первым, поздний answer не создаёт факт для неоткрытого вопроса.
- При ошибке отложения вопрос остаётся в прежней вкладке, черновик сохранён.
- До готовности endpoint допустим только честный «Следующий вопрос», без ложного статуса «Отложено».
  Это промежуточное состояние реализации, не финальное выполнение R6.04.

В схему GET вопросов добавить optional nullable `answer_text`, `answered_at`, `answer_fact_ids`.
`answer_text` и `answered_at` уже записываются в БД, но не входят в текущий публичный DTO целиком.
Факты связываются по действительному provenance вопроса, а не по порядку элементов массива.
Старые записи без связи не дополняются вымышленным ID. Текущая версия факта может отличаться от
первоначальной: для изменения нужно разрешить цепочку версий существующей моделью фактов.
Полная новая история всех черновиков/ответов не входит в эту задачу; существующая история фактов сохраняется.

После добавления одного PATCH ожидается 27 операций; E13 сверяет реальный OpenAPI заново,
а не полагается на это число как на неизменный норматив. Миграция нужна только если чтение фактической
схемы покажет отсутствие требуемого хранения; не создавать дублирующую таблицу ответов без необходимости.

## 7. Договор о кнопках включает обратные действия

| Контрол из аудита | Целевое действие | Возврат, повтор и pending |
|---|---|---|
| Открыть вопросы | Вход в кабинет указанного отеля | Пустой ID блокирует; повтор не закрывает страницу |
| Вопрос в очереди | Выбрать вопрос и открыть форму | Тот же ID не сбрасывает ввод; другой сохраняет черновик |
| Да, есть / Нет | Заполнить значение | Не POST; повтор сохраняет выбор |
| Не знаю / Следующий вопрос / Отложить | Неизвестность значения отделена от перехода и серверного отложения | Неизвестно не false; отложение только через H02 |
| Сохранить ответ | Один запрос с полным вводом | Pending блокирует повтор; одинаковый итог при любом способе выбора |
| Повторить загрузку вопросов | Новый GET после ошибки | Видимый pending, затем восстановление выбранного ID при наличии |
| Факт в карточке | Открыть сведения факта | Явный возврат к исходной строке и её фокусу |
| К отелю | Вернуться к конкретному исходному представлению | Подпись «К сведениям об отеле»/«К вопросу» по контексту |
| Как получен факт | Раскрыть/свернуть | Click, Enter, Space; aria-expanded; по умолчанию свёрнуто |
| История | Раскрыть/свернуть историю | Тот же контракт disclosure; текущий факт остаётся отдельно |
| Неверно, исправить | «Изменить» открывает редактор, «Свернуть» сохраняет ввод | Escape сворачивает, возвращает фокус; не притворяется отменой |
| Отмена | Сбросить к сохранённому значению и закрыть | Повторное открытие не возвращает отменённый текст |
| Подтвердить | Подтвердить текущий факт | Вся группа busy, вторая мутация не уходит |
| Сохранить уточнение | Проверить поля, отправить correct | Ошибка у поля, один запрос, видимый результат |
| Boolean-переключатель | Выбрать предметное значение | Radio semantics; неизвестное отдельно |
| Настройки | Открыть/закрыть | Триггер, Escape, снаружи; фокус возвращается; route change закрывает |
| Язык / Тема | Применить выбор | Панель остаётся открытой; черновик и выбранный вопрос сохраняются |
| Поиск отелей / логотип | Перейти на главный экран | Черновик сохранён; возврат восстанавливает контекст |
| Гости + / − | Изменить гостей в предпросмотре | Нижняя граница недоступна; рабочая форма не меняется |
| Заезд / Выезд | Изменить период в предпросмотре | Ошибка диапазона видна; узкая ширина — одна колонка |
| Номера, тарифы, услуги, галерея | Открыть соответствующие реальные данные предпросмотра | Назад сохраняет вопрос и ввод; пустые данные не имитируются |
| Открыть источник | Открыть существующий source_url | Новая вкладка сохраняет кабинет; повтор не закрывает внешнюю страницу |

Приоритет Escape: верхний overlay → вложенный редактор → очередь/предпросмотр; одно нажатие
не закрывает сразу несколько уровней. Disclosure и выбор вопроса имеют разную семантику:
выбранный вопрос не исчезает при повторном выборе. Анимация использует существующие примитивы,
прерывается безопасно и учитывает reduced motion; каждой строке отдельная анимация не нужна.

## 8. Что доказывает повторная проверка

H07 закрывает каждую строку R6.01–R6.15 ссылкой на проверку и кадр, где это нужно.
Проверить открытие/закрытие/повтор, быстрые клики, Tab/Enter/Space/Escape, отмену, Back/reload,
смену отеля, задержку, ошибку и повтор, follow_up, конфликт, один вопрос, все отвечены и пустую очередь.
Матрица: 375/1440, RU/EN, обе темы, шрифт 125%, настоящий browser zoom 200%, reduced motion.

Контролируемые браузерные ответы проверяют интерфейс. Реальная запись проверяется отдельно
на изолированной PostGIS с FakeLLM и синтетическими отелями из [демо](../hotelier-demo/README.md).
Действующий стенд с платным провайдером не переключать ради теста. Полный verify запускать
под поддерживаемым Node >=22.18. Отсутствие ошибок axe не заменяет ручной обход фокуса.
Exploratory CLS из исходного аудита не использовать как результат нового performance-замера.
