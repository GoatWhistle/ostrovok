| AL11 | Медленная/ошибочная загрузка, нет WebGL, затем переходы между экранами | Поиск работает сразу, резервный кадр доступен; один GL у обложки, нет оставшихся циклов и утечек |
| AL12 | Осмотреть 375/1440 × light/dark × RU/EN и пройти клавиатурой | Нет перекрытий/скачков; понятные пауза/повтор; полный текст для скринридера; панорама подписана иллюстрацией, панели прототипа нет |

Метод таймингов: в автоматической проверке управлять общей шкалой приложения и проверять состояния
на 200/2000/7400/8400/8600/8800/9600/16400 ms, а также непосредственно перед границами.
Отдельно проверить длительность прорисовки маршрута 1200 ms от его собственного старта.
На 7400 ms результат первого сюжета уже полностью виден, на 8400 ms начинается второй,
на 16400 ms достигнут неподвижный финал. Пауза не включается в активную длительность.
Для визуального подтверждения повторить реальное воспроизведение с кадрами/записью и зафиксировать
задержку от расчётного события до ближайшего отрисованного кадра; не добавлять её к постановочным паузам.

На каждой из восьми комбинаций viewport/тема/язык проверить оба сюжета и финал, высоты карточек,
подписи и настоящий ввод. Пауза должна замораживать и мигание курсора. Проверка доступного полного
текста не считается полноценным прогоном скринридера; метод и ограничения записываются отдельно.
Тест отсутствия WebGL и задержки ресурсов обязан проверять отправку настоящего запроса до загрузки сцены.

## Порядок коммитов и единственный итоговый push

| ID | Проверка | Условие приёмки |
|---|---|---|
| AG01 | Сверить пункты плана с локальными коммитами и проверками | После каждого завершённого проверенного пункта есть отдельный коммит; самостоятельные результаты не свалены в один финальный |
| AG02 | Сверить журнал выполнения публикации | До завершения всех обязательных E00–E18/H01–H07 промежуточные push отсутствуют |
| AG03 | Проверить состояние непосредственно перед итоговым push | Все пункты и проверки завершены, итоговые документы закоммичены; публикуется вся готовая ветка одним финальным push |

Для пунктов проверки без правок кода коммит содержит отчёт. История коммитов сама по себе не доказывает
отсутствие промежуточных push: действия публикации фиксируются в журнале выполнения. Эти проверки
применяются к разрешённой реализации; текущий журнал находится в [progress.md](progress.md).

## Матрица и данные проверки

Основные состояния проверить на 375/1440, RU/EN, light/dark, neon/toy-town; для кабинета стиль карты
важен только в предпросмотре. 768/1024 нужны для границ раскладки, 1920/2560 — длины строк.
Снимки подписывать: SHA, сценарий, viewport, язык, UI-тема, map style, данные и метод проверки.
Отдельно фиксировать реальные GET, реальные записи в изолированную PostGIS/FakeLLM и контролируемые
браузерные ответы. Последние не доказывают серверное сохранение или работу платной модели.

## Производительность проверяется по заранее записанному методу

Это предлагаемые цели, не измеренные показатели. В E00 закрепить оборудование и условия до прогона;
если цель пересмотрена, сохранить прежнюю цель и причину, не переписывать неуспешный результат.

| Проверка | Выборка/метод | Цель |
|---|---|---|
| Смена готового локального оформления | 10 смен после прогрева, от действия до согласованного кадра | p95 ≤250 мс |
| Панорамирование | 3 участка × 30 секунд, тот же viewport и устройство | p95 времени кадра ≤33 мс после адаптации качества |
| Серверные MVT | Не менее 20 тайлов разных zoom, 5 повторов; отдельно cold/warm | Предварительная цель warm p95 ≤250 мс; размер ответа публикуется |
| Повторные переходы | 10 циклов панель/страница/карта/стиль | 1 основной instance, максимум 2 GL; ресурсы не накапливаются |
| Скрытая карта | 30 секунд полной страницы после стабилизации | Нет её непрерывного animation loop и новых mesh/scene-задач |

Headless FPS и одиночный CLS исходного аудита не считаются измерением плавности реального устройства.
Индивидуальные дома меньше пикселя на масштабе страны не являются критерием; проверяется согласованный LOD.

- Backend: `uv run ruff check .`, `uv run mypy .`, `uv run pytest tests/unit`;
  для хранения/тайлов/стенда также `uv run pytest tests/integration` и имеющиеся контрактные проверки.
- Документы: `node skills/docs-writing/check-links.mjs work/frontend-evolution`;
  память: `python3 .claude/scripts/context_budget.py`.

Для сдачи реализации нужен отчёт по E00–E18/H01–H07, A01–A43/AH01–AH24/AL01–AL12/AG01–AG03, всем 15 замечаниям
и кнопкам аудита. Невыполненные/непройденные проверки перечисляются явно. В задаче написания
спецификации выполняется только проверка документов, без запуска реализации и платных вызовов.
