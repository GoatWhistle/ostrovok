# Маршрутизация чата

Поиск запускается только на search-намерение. Консультация и вопросы о выбранном отеле сохраняют поисковый контекст, выдачу, карту и выбранный факт. Открытие истории не запускает поиск.

Один структурированный LLM-вызов получает сообщение, последние восемь реплик, прежний поисковый запрос и ограниченный контекст текущего выбранного отеля. Возвращает режим search/consult/hotel, актуальный запрос либо ответ. Для search сохраняет/меняет условия; для consult/hotel запрос отсутствует. Неуверенность и ошибки классификации не запускают поиск.

Отель: существующий GetHotelCard, реальные сведения с датами/источниками, без вызовов поставщиков и без вымышленных цен/наличия. История не служит источником фактов. Детерминированный offline-адаптер вычисляет маршрут из входа и отвечает по доступным данным.

Хранение: существующие nullable effective_query/search_snapshot; новые миграции не нужны. В snapshot сохраняется ID реплики, породившей поиск. Публичное search_message_id связывает выдачу с нужным сообщением, чтобы консультация не выглядела новым поиском. OpenAPI обновляется до реализации.

Проверки: маршруты и контекст, отсутствие вызовов поиска на консультациях/загрузке истории/ошибке модели, выбранный отель и смена выбора, сохранение выдачи и search_message_id; реальная БД с изолированным созданием/удалением для nullable сохранения; фронтенд не сбрасывает выбранный факт при консультации. Без LLM и перезапуска стенда.


Реализовано и проверено на feat/hotel-agent-mvp / 8e229bc: 630 unit/contract, 11 PostgreSQL integration, 328 frontend-тестов; Ruff/format, mypy350, import3 и frontend verify прошли. 23 сценария маршрутизации, 11 проверок двух облачных адаптеров через локальные HTTP-фикстуры, HTTP+реальная изолированная БД, сохранение фокуса карты и привязка кнопок к поисковой реплике RU/EN.

Исправленные проверки: отсутствовал registry fixture; тест уточнения не задавал обязательный location_hint; первый БД-тест смешивал loop TestClient с pytest-loop при закрытии пула — переведён на ASGITransport в одном loop, временная БД удалена. Контракт выявил, что viewport=null не был описан: nullability уточнена. Временный вызов api:types сперва читал старый запущенный API, затем типы полностью пересозданы из канонического docs/api/openapi.yaml через API_SCHEMA_URL. Замечание о кириллице в frontend-тесте исправлено. Финальные проверки прошли.

Рабочий стенд в рамках задачи не перезапускался, живые LLM/API источников не вызывались. Реальное семантическое качество облачной маршрутизации не измерено; полный e2e со сценой не повторялся, его предыдущие ограничения остаются в истории. Внешние тулзы в консультации пока не вызываются: сведения о выбранном отеле берутся из сохранённой карточки.
