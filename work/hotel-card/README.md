# Карточка отеля: отдельная ветка и стенд

2026-10-28. Ветка `feat/hotel-card-tabs`, worktree `.worktrees/hotel-card`, база `a9529e2` (`fix/search-map-animation`).

Собранный фронтенд: http://localhost:18087/?hotel=w51106908&tab=hotels

Демо с подтверждённой доплатой: http://localhost:18087/?hotel=h_demo_hotelier_answered&tab=hotels

Второй отель содержит явно обозначенные тестовые данные; доплата 500 RUB получена из API, а не добавлена интерфейсом.

## Запуск

Требуется существующий API на 8000 и сервер карт на 8080. Из `frontend/` с Node >=22.18:

```bash
npm run build
API_URL=http://localhost:8000 MAP_ASSET_URL=http://localhost:8080 npm run preview -- --host 0.0.0.0 --port 18087 --strictPort
```

На текущей машине процесс запущен с Node 24 через `/tmp/hotel-card-bin`. Зависимости скопированы в отдельный node_modules; кэш соседнего worktree не используется.

## Изменение

Один ряд вкладок «Об отеле», «Рядом», «Удобства», «Платные услуги». Отсутствие подтверждённых доплат скрывает последнюю. Действия номера/факта/карты сохраняют прежний интерфейс HotelDetails. Фон и края панели берутся из существующего рабочего пространства. В глобальные стили, API, БД, данные и карту изменений нет.

Подробные ограничения данных и решение: [ADR](../../docs/adr/0004-hotel-card-sections.md).

## Слияние

- Сначала сохранить общую базу поисковой ветки `a9529e2`, затем перенести отдельный коммит карточки; работу ночной карты и отельера можно объединять независимо.
- Основная область карточки: `frontend/src/features/hotel-details/`. Новые части собраны в `panels/`.
- Параллельная работа отельера добавляет тот же `shared/ui/forms/tabs/`. Сохранить одну реализацию с контролируемыми `label`, `value`, `onChange`, `options`. Версия карточки добавляет необязательные `compact`, `option.icon`, `option.id`, `option.panelId`; вызовы отельера остаются совместимыми. Не создавать второй экспорт Tabs.
- В `shared/ui/index.ts` сохранить один экспорт Tabs и остальные добавления другой ветки. В RU/EN `explore.json` сохранить объект `hotelCard` и независимые ключи отельера.
- `docs/adr/0004-hotel-card-sections.md` отдельный: дополнения ночной карты в `docs/design-decisions.md` не затрагиваются.
- Shared HotelDetails используется также на странице отельера. Его публичные props сохранены, но встроенный просмотр отеля получит те же вкладки.
- Не переносить node_modules, dist и скриншоты. Полное слияние других незавершённых веток пока не выполнялось.

Результаты проверок и ограничения: [validation.md](validation.md).

В ходе оценки также обновлены описание и происхождение факта: поставщик больше не повторяет расположение и услуги в About. Структурированный текст перенесён в тематические разделы и свёрнут; даты происхождения показаны без отдельной плашки, служебные коды раскрываются отдельно. Дополнительная область слияния — `features/fact-details/fact-provenance*` и необязательный props.fact; публичные действия FactDetails сохранены.

Основные строки вкладок унифицированы через новую общую композицию `bodyMedium` в `shared/styles/compose.module.css`. При слиянии сохранить это добавление: существующие роли и глобальные токены не менялись.

Общий Disclosure получил необязательный `revealOnOpen`, включённый только для «Все факты и источники». При объединении сохранить этот опциональный props: прочие раскрытия не прокручиваются. В Amenities пояснения теперь привязаны к названиям строк по точному совпадению текста; непривязанные исходные условия остаются в отдельной текстовой группе. Подпись под расстояниями удалена.

Nearby показывает весь список сразу. Кнопки раскрытия нет. «Описание» с расположением стоит первым блоком About, перед фактами, номерами и условиями. Удобства сгруппированы в свёрнутые категории, открыта только одна; описания раскрываются у услуги. Категории16px/750, подпункты13px/650, пояснения14px/450. Размер подпунктов уменьшен по последнему пожеланию пользователя. Категории и строки источника имеют локальные Lucide-иконки.

Дополнительные общие изменения при слиянии: Disclosure получил совместимые optional open/onOpenChange, iconOnly, expandedTitle; реестр Icon и RU/EN словари дополнены. Сохранять новые имена и независимые добавления соседней ветки. Браузерный e2e/hotel-details-width.spec.ts проходит категории по очереди, проверяя весь длинный список.

DetailsSection получил optional collapsible; используется только для фактов карточки и условий проживания, начальное состояние свёрнуто. FactList передаёт этот флаг, остальные вызовы не меняются. RoomsTeaser использует обычный RowButton; общий источник описания номеров больше не рендерится в RoomsScreen.

RowButton.leading теперь необязателен: без иконки слева сетка имеет два столбца. Существующие вызовы со значком не меняются. Строка номеров использует этот режим, значок номера стоит справа. Фон surface-raised выделяет переход постоянно; отрицательные поля компенсируют внутренний padding, сохраняя левую линию текста. При слиянии сохранить optional leading и правило data-leading в entities/evidence/row-button.
