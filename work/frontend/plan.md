# Фронтенд поиска отелей с 3D-картой

План и ревью: 25.10.2026. Ветка `feat/hotel-frontend` основана на
`origin/feat/hotel-agent-mvp`, коммит `adb6014`. Пользователь разрешил реализацию,
проверку и публикацию этой ветки после завершения.

## Direction contract

**THESIS:** свойство отеля связывает результат поиска, геометрию на карте и доказательство.
**OWN-WORLD:** выбранный пользователем Mapbox: глубокие тёмные поверхности, синие действия,
пилюли управления, спокойная геометрическая типографика. Светлая тема сохраняет те же роли.
**STORY:** запрос → результаты → отель → свойство → источник; отельер уточняет неизвестное.
**FIRST VIEWPORT:** верхняя навигация; слева поиск и результаты, справа большая 3D-сцена;
подробности выбранного отеля раскрываются рядом с картой. На телефоне список, карта и детали
доступны отдельными переключаемыми представлениями. Главная кнопка запускает поиск.
**FORM:** рабочее пространство Operate, code-led; пользователь задал мир присланным референсом.
Seed не запускался: Impeccable недоступен, применён разрешённый fallback по контексту проекта.
**FINISH:** unreviewed and undocumented is unfinished; this build ends with the finish review,
the verdict, DESIGN.md, and every shipping raster carrying its provenance.

## Контракт и действующий бэкенд

Источник форматов — [OpenAPI](../../docs/api/openapi.yaml), 13 методов. На полученном коммите
реализованы `/health` и `/characteristics`; unit/contract: **147 passed**. Это не готовые
поиск, persistence или сцены. Бэкенд не изменяем в рамках фронтенда.

| Интерфейс | API под `/api/v1` | Этап |
|---|---|---|
| Статус сервиса, справочник признаков | GET `/health`, `/characteristics` | 1 |
| Регион и начальная камера | GET `/regions` | 1 |
| Поиск, распознанные условия, выдача | POST `/search` | 2 |
| Отель, комнаты и факты | GET `/hotels/{hotel_id}` | 2 |
| Здания, фасады, контекст и камеры | GET `/hotels/{hotel_id}/scene` | 3 |
| Геометрии выбранного свойства | POST `/geo-features:batch` | 3 |
| Источник, история, конфликты | GET `/hotels/{hotel_id}/facts/{fact_id}` | 4 |
| Вопросы и ответ отельера | GET `/hotelier/{hotel_id}/questions`, POST `/hotelier/questions/{question_id}/answer` | 4 |
| Подтверждение и исправление | POST `/facts/{fact_id}/confirm`, `/facts/{fact_id}/correct` | 4 |
| Сравнение 2–5 отелей | POST `/compare` | 5 |

Недоступный метод показывает ошибку и повтор. Примеры из YAML не становятся данными интерфейса.
Кеш и запросы проходят через TanStack Query и `openapi-fetch`. Типы генерируются из локального
контракта; runtime OpenAPI сравниваем с ним по мере реализации бэкенда.

## План реализации

1. Сохранить референс, JSON токенов и их происхождение. Прочитать текущие примитивы и проверки.
   Привести PRODUCT/DESIGN к выбранному продукту. Перенести палитру в токены, сохранить две темы.
2. Сгенерировать API-типы из `docs/api/openapi.yaml`. Учесть `servers` с `/api/v1`: пути в
   контракте короткие, префикс добавляется клиентом один раз. Разделить транспортные ошибки,
   пустую выдачу, неизвестные поля и недоступность бэкенда.
3. Собрать оболочку: запрос, регион, список признаков и результатов, управление картой,
   выбор отеля. Все тексты RU/EN; данные и объяснения сервера сохраняют исходный язык.
4. Подключить MapLibre локальной зависимостью. Отрисовывать контуры, здания по известным высотам,
   фасады и GeoJSON из API. Камеры применять по явному выбору; новая команда прерывает старую.
   Без высот остаётся 2D-контур. Без WebGL сохраняются список и факты.
5. Связать выбор свойства с кешируемой пакетной загрузкой `geo_refs`, подсветкой и доказательством.
   Наведение, клавиатурный фокус и нажатие на телефоне дают эквивалентный доступ.
6. Добавить карточку факта, конфликтующие/устаревшие значения, вопросы отельеру и мутации.
   После ответа инвалидировать затронутые карточки и выдачу; исключить повторную отправку.
7. Добавить сравнение по одинаковым ключам характеристик. Неизвестное значение остаётся неизвестным.
8. Пройти rules/typecheck/lint/tests/build; проверить живой backend на desktop/mobile,
   RU/EN и обе темы. Отдельные тестовые ответы допустимы только в `tests/`.
9. Выполнить ревью, исправить замечания одним пакетом, подтвердить результат, затем commit/push.

## Ревью плана до кода

| Риск | Решение |
|---|---|
| `pending` требует повторить поиск с `query_id`, но такого входного поля нет | Автоматический polling выключен до уточнения протокола; пользователь может повторить поиск |
| Геометрия описана как произвольный `object` | Проверять GeoJSON и числа перед передачей WebGL; не рисовать повреждённые данные |
| `value` и `qualifiers` не имеют фиксированной структуры | Использовать `value_type` и безопасные форматтеры; неизвестный формат показывать явно |
| Подложка, terrain encoding и локальные тайлы не описаны полностью | Сцена на данных API работает без платных ключей; загрузка terrain только при совместимом источнике |
| Нет Cera Pro и лицензированных файлов | Использовать указанный пользователем system fallback; не скачивать коммерческий шрифт |
| Белый текст на Signal Blue может не пройти контраст | Проверить пары, использовать предоставленный Deep Signal для подходящей семантики действий |
| Маркетинговый max-width и all-caps против правил рабочей области | Полная ширина приложения, sentence case, компактная типографика; визуальная палитра сохраняется |
| Авторизация отельера в контракте не определена | Не имитировать защищённый вход; сервер отвечает за доступ, UI обрабатывает 401/403 |

## Архитектура фронтенда

`app → pages → features → entities → shared`. Страница соединяет поиск, выбор отеля,
карту и просмотр факта через props; соседние features не импортируют друг друга.
Состояние запроса и выбранных ID отделено от серверного кеша. Карта не пересоздаётся при каждом
обновлении React, обработчики и WebGL-ресурсы освобождаются при закрытии.

Существующие Button, Segmented, EmptyState, ErrorState, Skeleton, переключатели темы/языка
и API-клиент расширяются по необходимости. Стек остаётся React/Vite/TypeScript/CSS Modules;
Tailwind из экспортного блока `@theme` не подключается.

## Критерии завершения

- На первом экране виден запрос и понятное состояние данных; ошибки не выглядят успешной выдачей.
- Доступные методы используют настоящий backend. Остальные готовы по контракту и показывают
  недоступность до появления соответствующего метода.
- Выбор отеля/факта синхронизирует список, сцену и доказательства без вымышленных значений.
- Камеру можно прервать, reduced motion соблюдается; основная навигация доступна без карты.
- Работают клавиатура, 375/1440 px, RU/EN и светлая/тёмная темы.
- Проверки, результаты браузерного ревью и ограничения записаны перед публикацией.
